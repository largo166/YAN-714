> 红线(用户第5条):块1 动的 staging 是张文正用、hotfix1 刚验的心脏链路。最小改动,不顺手重构,不破坏已验链路。完成必跑第5条回归。

## staging 现有链路（读后确认）
1. 前端 `CleanupWizard.onPickSelect(abs)`:选一个目录 → `api.staging([abs])` → `setPickedPaths([abs])` → step2 渲染 `staging.groups`。
2. 后端 `build_staging(paths)`:每个「顶层选中项」= 一个 group(`group_for`),`_iter_files` **递归全部文件**进该 group,project_hint=选中目录名。**当前:选父目录 → 整个父目录一个 group(错,应每个子目录一个)。**
3. 执行:`doIngest()` 用 `pickedPaths` → `ingestStart(pickedPaths)` → 后端 `_ingest_worker` 按 `_group_by_source` 分组、每 source_dir 建一个项目。

## A 语义要改什么（最小集）
### 后端 `staging.py`（核心改动,但**加分支不重写**）
- `build_staging` 加一层:对每个选中的**目录**,判断——
  - **有一级子目录且子目录内有文件** → 对每个一级子目录调 `group_for(子目录)`(每个=一个 group,project_hint=子目录名);父目录**直属散落文件**单独计数,不入任何 group(记 `loose_files` 计数返回)。
  - **无子目录(叶子)** → 保持现有行为:整个目录一个 group。
- **保留** `_iter_files`/`group_for`/去重/type_stats 逻辑不动——只改"选中目录→怎么定 group 根"。
- 新增字段(向后兼容,默认值):
  - `StagingGroupOut`: `+ reject_reason: str=""` `+ warn_reason: str=""`(调 project_naming)
  - `StagingOut`: `+ loose_files: int=0`(父目录直属散落文件数,前端提示行用) `+ selection_mode: str="single"`(multi/single,前端选默认全勾/单项目切换)

### 前端 `CleanupWizard.tsx`（step2 加"项目确认",用现有步骤范式,不重做向导）
- staging 返回多 group + selection_mode:
  - multi → step2 顶部"检测到 N 个项目",每 group 一行带勾选框(默认全勾),warn_reason 标黄。
  - 顶部切换"其实是同一个项目 → 整目录作为一个"(覆盖为 single)。
  - loose_files>0 → 显示一行"该目录下有 N 个散落文件未归入任何项目,本次不入库"(**忽略但不静默**,用户第1条)。
- 执行:`pickedPaths` = **勾选的 group.source_dir 列表**(不再是 `[abs]`)。ingest 现有按 source_dir 建项逻辑天然支持多路径,无需改 ingest worker。
- reject_reason 命中的 group:不可勾+红字(理论上 staging 阶段父目录选取一般不触发 reject,reject 主要在 ingest 入口兜底,已块2 落地)。

### `lib/api.ts`
- `StagingResult` TS 类型 + `StagingGroup` 加 `reject_reason?/warn_reason?`、顶层加 `loose_files?/selection_mode?`(可选,向后兼容)。
