## 0. 一句话定义（🔒 用户已锁定）

**共创营地 = 建筑前期"图文成果生产台"，不是"AI 聊天 + 技能商城"。**

它服务事务所前期最真实的两件事：① 把项目资料变成能汇报的 PPT 图文底稿；② 把缺失的视觉表达补成可用意向图。两者**共用一个中枢：图片资产池**。生 PPT 与生图不是两个孤立功能，而是同一条"图文汇报生产线"的前后手。

**主线（🔒 用户已锁定）**：
```
资料 → 判断 → 图文页 → 缺图识别 → 生图补位 → 回到图片池 → 导出 PPT
```

**总纲铁律（🔒）**：**AI 搭骨架，建筑师做判断；AI 给候选，建筑师确认。**

## 0.5 从用户真实操作痕迹反推的证据（【本机实证】，2026-07-10 核）

> 用户要求"结合我原来在 codex/claude/本地系统上操作生图和 PPT 的记录"分析。主控在本机可及范围内核出以下真实痕迹——**这是比竞品研究更硬的一手证据，直接修正/坐实了下方多个答案**。
> 边界诚实：只覆盖本机 + 本项目可访问范围；用户在云端/别机 codex/claude 的历史读不到，未纳入（不编造）。

**证据 A · 本机有 60 份真实 PPT，其中 23 份是建筑投标/方案类。**
- 页数分布（23 份）：`[4,5,6,10,13,13,13,13,13,14,14,20,25,32,32,32,33,33,36,36,38,42,53]`
- **中位数 20 页 · 均值 23 页 · 主分布 11-35 页**；分档：≤10页4份 / 11-20页8份 / 21-35页6份 / >35页5份。
- **一簇 13 页**（多份）= 轻量提案版的自然聚集；另一簇 32-36 页 = 完整方案版。
- 命名铁证：`缝合城市·云上公园——望府提案.pptx`(14p) → `完整版33p` → `改丑版32p` → `改丑版32p_v2` —— **同一投标经"提案→完整→改→再改v2"反复迭代，绝非一次生成即终稿**。

**证据 B · 两种建筑 PPT 图文比截然不同（页型分化的实证）：**
- **判断/策略型**（如 `那河沟AB地块前期策略地图` 20p）：图极少（0.2/页）——**文字判断为主，图是点缀**。
- **方案文本型**（如 `260705方案文本` 42p）：图密集（2.0/页，19页≥3图，单页最多6图）——**图为主**。
- → **坐实：页型必须分化**（判断型页 vs 图册型页），不能一套通用版式套所有页。单页图数 1-6 张真实存在，但**多数页 0-1 图**。

**证据 C · ROM-AI 本地系统里生图/PPT 成果几乎为零，但图片资产 15639 张。**
- `skill_results` 表仅 1 条（judge），**零 PPT 落库、零生图落库**；本机 pptx 只有 python-pptx 库自带模板（即：**ROM-AI 从未真正产出过一份 PPT**）。
- 但 `backend/data` 下有 **15639 张图片**（大量从 PPT/PDF/Word 抽出的资产）。
- → **这个悬殊对比是整份定义最重要的信号**：ROM-AI 的**图片资产（原料）极其充沛，但"把原料变成 PPT 成果"这条产线完全没通**。共创营地第一阶段要打通的正是这条断链——**不是缺原料，是缺"原料→成果"的生产动作**。

**这三条证据对下方答案的直接影响（据实修正）：**
1. **PPT 默认页数 → 改建议为「默认 20 页，可选 13/20/33」**（原建议 12 页，被真实中位数 20 推翻；13=提案版、33=完整版对应真实两簇）。
2. **页型库 → 必须含"判断型页(少图/无图)"与"图册型页(多图)"两态**（证据 B）。
3. **"完成"的定义 → 被采用/被沉淀**再获印证：真实工作是"反复改到能上会"（33p→32p→v2），不是"生成一次就完"。
4. **第一阶段价值锚点 → "打通断链"**：原料(15639图)已在、产线(0 PPT)未通——第一阶段做的就是这条产线的最小闭环，ROI 极高（从 0 到 1）。

## 2. 五个核心决策点（用户点名最该先答；给💡建议答，🔨等你拍）

### Q核1 · 共创营地第一屏 = "两个主工作流" 还是 "技能总入口"？
- 💡**建议：两个主工作流。** 首页两个主按钮 `生成 PPT 底稿`｜`生成项目意向图`；22 技能收进 `/` 命令与任务流，不平铺。
- 依据：用户倾向明确（"两条主线组织技能"）；agent 工作区研究结论（技能应是"任务形态预设"，不是让用户拼）；【代码实证】22 技能现平铺在 AgentCampBoard，需收编。
- 🔨你拍：接受"双主入口 + 技能收进 /"？ 还是保留技能库为可见二级入口？

### Q核2 · PPT 第一版 = "页级图文底稿" 还是 "可编辑 PPT 工作台"？
- 💡**建议：页级图文底稿。** 生成物 = 页级卡片（标题/核心判断/要点/视觉建议/来源），不是 Markdown 一坨、也不是完整 PPT 编辑器。
- 依据：用户已锁（L3）；【研究实证】Gamma/Beautiful.ai 共识"大纲=交付物=最便宜的确认关，别急着到像素"；【代码实证】现在 PPT 成果塞在 `SkillResult.output_json`，页级卡是净新增的呈现层。
- 🔨你拍：无异议则升为🔒。

### Q核3 · 图片资产池是否正式升级为 PPT 与生图的共同中枢？
- 💡**建议：是，正式升级。** 三角色：取料（PPT 图槽按 asset_type 批量填）／补位落点（缺图从槽点开生图）／回流（生图择优入池带血缘）。
- 依据：用户已锁（L2）；【代码实证】图片提取器已存页码/slide-no/类型/尺寸；`PptExportIn.slide_asset_ids` 已铺"每页绑哪个资产"通路；`FileAsset.asset_type` 已含 render/reference/plan…。
- 🔨你拍：无异议则升为🔒。（后续净新增见 §9 数据结构）

### Q核4 · 生图入口 = 独立入口 还是 主要从 PPT 缺图槽触发？
- 💡**建议：主入口从"PPT 缺图槽"触发；首页那个 `生成项目意向图` 按钮 = 同一流程的另一入口，但也必须先落到"这张图服务什么"。** 绝不设"纯生图孤儿按钮"。
- 依据：生图流强结论（"生图面板只能从底稿空图槽点开，入口即携带绑定，确认那步写血缘"）；用户已锁生图=补位（L4）。
- 🔨你拍：首页 `生成项目意向图` 按钮点开时，是否强制先选"服务哪个项目/哪类用途"再进生图（避免变成孤儿玩图）？建议强制。

### Q核5 · 哪些结果必须进知识沉淀，哪些只是一次性成果？
- 💡**建议**：**进沉淀** = 用户确认过的判断（→ 项目智能中心认知）、被采用的生图（带"服务哪页/哪判断"血缘）、导出过的 PPT 底稿版本。**一次性** = 未确认的草稿、被弃的变体、纯探索没落页的生图。
- 依据：用户总问点出"什么被沉淀、什么被导出"是产品身份的核心；【代码实证】`SkillResult` 已落库可回查，但"确认→回流认知"是净新增。
- 🔨你拍：判断"确认后进项目智能中心"这条要不要第一阶段就做，还是进 backlog？（建议：第一阶段生图/PPT 先跑通，判断回流认知进中期 backlog——见 §11）

## 3. 十二组细问 · 逐条给建议答（🔒/💡/🔨）

> 为控制篇幅：用户已明确的直接标🔒；能据研究+代码给答的标💡；真需你拍的标🔨并列选项。

### 一、用户与场景
- 第一用户：💡**主创 + 方案建筑师**（他们对"底稿/意向图"负责）；助理可先跑草稿，主创确认。🔨确认第一用户是否就是主创。
- 最常 3 任务：💡① 投标前把资料理成汇报底稿 ② 缺图补意向图 ③ 回看/改上一版。
- 救火 vs 启动：💡两者都要，但**第一阶段优先"投标前把资料变底稿"**（最高频痛点）。
- 带任务来 vs 带混乱资料来：💡**带一堆资料+混乱问题来**——所以入口要"选项目→自动理出底稿"，不是空对话框。
- 个人流 vs 项目组共识流：💡第一阶段**个人工作流**（主创/助理单人跑）；项目组共识（指派/评论）进长期 backlog。
- 谁确认：🔒主创确认关键判断与配图；助理可先跑生成。
- 甲方/老板/团队口径不同：🔨**中期**做（甲方版/内部评审版/高层速览版模板），第一阶段单口径。

### 二、产品身份
- 是什么：🔒**成果工作台**（非纯聊天入口、非技能启动器、非泛设计副驾）。
- 与项目智能中心边界：💡中心 = "看清项目条件/风险/裁决"（认知源）；营地 = "把认知变成图文成果"（生产台）。营地**读**中心的认知，**回写**确认过的判断。
- 与数据基地边界：💡基地 = 资料入库/检索/图片资产池底座（仓库）；营地 = 消费资产池产出成果（工作台）。
- 与会议纪要边界：💡纪要 = 裁决来源；营地 PPT 的"判断/来源"可引用纪要裁决。
- 首页展示"能做什么" vs "正在推进什么"：💡**优先"正在推进什么"**（当前项目的底稿/意向图进度）+ 两个主入口；技能是手段不是主角。
- 22 技能平铺？：💡**收进任务流 + / 命令**，不平铺（同 Q核1）。
- 核心 KPI：🔒**成果被采用次数**（主创愿拿它当第一次讨论底稿），不是生成次数。

### 三、PPT 工作流
- 终稿 vs 底稿：🔒**图文研判底稿**。
- 默认几页：🔨**建议默认 20 页，可选 13/20/33**。【本机实证】23 份真实投标 PPT 中位数=20 页、主分布 11-35；真实存在两簇——13 页(提案版)、32-36 页(完整版)。**原"12 页"建议已被真实数据推翻。** 你拍：默认 20 + 三档预设(13提案/20标准/33完整)？
- 页型是否固定：💡**半固定 + 两态**——给建筑投标页型库，默认排一套，可增删改序。【本机实证 证据B】页型必须分"判断型页(少图/无图，如策略地图)"与"图册型页(多图，如方案文本)"两态。
- 页型库（💡建议集，🔨你增删）：封面 / 项目理解 / 区位 / 场地条件 / 竞品标杆 / 策略 / 概念 / 货值(产品) / 风险 / 下一步(行动项)。
- 每页字段（💡建议）：**标题 / 核心判断（一句）/ 要点 / 视觉建议(建议图类型) / 图槽 / 讲稿(可选) / 来源**。🔨"讲稿"第一阶段做不做（建议：留字段，第一阶段可空）。
- 按对象 vs 按阶段生成：💡**第一阶段按"项目阶段/通用投标前期"生成单口径**；按对象（甲方/老板/评审）进中期。
- 生成后最常改：💡标题、逻辑(页序)、图片、措辞——所以这四样都要可编辑。
- 页锁定：💡**要**——用户确认某页后标"已锁"，AI 重新生成不覆盖已锁页（防"改了又被 AI 冲掉"）。🔨确认要此机制。
- 保留来源引用 vs 导出隐藏：💡**底稿内显示来源，导出 PPTX 时可选隐藏/保留**（甲方版通常隐藏、内部版保留）。
- 导出后能否回 ROM-AI 继续编辑：💡**第一阶段：导出是单向出口**（导出 .pptx 后在 PowerPoint 改）；"读回已有 PPT 续编"= Plus AI 能力，进长期 backlog。

### 四、生图工作流
- 服务什么：🔒概念图/氛围图/立面意向/材料板/场景图/示范区图（都是"补位"）。
- 入口：🔒**主要从 PPT 缺图槽进**（Q核4）。
- 先确认提示词：🔒**必须**先出提示词草案→确认→才生成（L5）。
- 提示词分段（💡建议）：画面描述 / 建筑控制 / 材料 / 光影 / 禁止项。🔨第一阶段是否做分段（建议：第一阶段先做"整段提示词草案可编辑"，分段进中期）。
- 选参考图 + 上限：💡可选参考图；【代码实证】后端 `ref_asset_ids` 上限 16，**建议第一阶段 UI 限 1-4 张**（够用、简单）。
- 参考图来源：💡**项目图片池优先**；临时上传进 backlog（第一阶段先只从池选，避免旁路）。
- 结果入池：🔒默认入池（L6）。
- 标记 AI 生成：🔒必须标（L6）；【代码实证】现靠 asset_type=render 隐含，**建议加显式 `is_ai/source` 字段**（净新增，见 §9）。
- 默认几张：🔨【代码实证卡点】后端 `generate_image` **n=1 硬编码**。建议**第一阶段默认 1 张**（最省，先跑通闭环）；"3 张变体扇"= 多次调用，进中期。你拍。
- 失败显示：🔒诚实四态——没 key(not_configured)/模型失败/参考图不支持/超时；【代码实证】keyless→not_configured 已具。

### 五、图片资产池
- 图库 vs 视觉证据库：🔒**项目视觉证据库**（带来源/类型），不是通用图库。
- 类型分（💡）：效果图/总图/平面/竞品/现场/材质/示意/AI生成；【代码实证】asset_type 已有大部分。
- 可信度分级：💡**要**——原始资料图 / 用户上传图 / AI生成图 三级（净新增 `trust_level`，见 §9）。这是"防假图混入证据页"的关键。
- 保留来源文件/页码/幻灯片号：🔒【代码实证】提取器已存这些元数据。
- 人工改类型：💡要（数据基地图片资产已支持改 asset_type，营地复用）。
- 配图：系统推荐 vs 用户选：💡**第一阶段用户主动选**（EasyMap 式手动换图，比 AI 乱配可靠）；自动推荐进中期。
- 一页几张：💡**1 主图**为默认；1主2辅进中期（页型模板决定）。
- 缺图页自动建生图任务：💡**标"缺图"+ 提供"去生图"按钮**，不自动建任务（守不静默）。
- 一键填回 PPT 页：🔒【代码实证】`slide_asset_ids` 通路已铺，UI 净新增。
- 三来源(本项目/跨项目/标杆)：💡本项目 + 跨项目【代码实证已落 `listAllAssets`】；标杆案例库进长期。

### 六、判断与证据
- 每判断必须有来源？：💡**要**（这是 ROM-AI 区别于"通用 AI PPT"的命门）；【代码实证】`SkillResult.sources_json` 已有出处底座。
- 来源来自：💡项目文件/会议纪要/甲方画像/竞品资料/人工输入。
- 无证据判断怎么显示：💡**标"待确认"，不静默输出成事实**。🔨确认此口径。
- 确认过的判断进项目智能中心？：🔨**建议进（中期）**，第一阶段先不做回流（Q核5）。

## 4. 第一阶段 · 只做什么（🔒 用户已锁 + 💡最小闭环）

**做（一个朴素但闭环的东西）**：
1. 共创营地首页两个主按钮：`生成 PPT 底稿`、`生成项目意向图`。
2. PPT 生成 = **页级卡片**（标题/核心判断/要点/视觉建议/来源），不是 Markdown 一坨。
3. 每页一个图片槽，能从图片资产池选图。
4. 无合适图 → 标"缺图"，可去生图补。
5. 生图 = 先出提示词草案 → 确认 → 才生成。
6. 生图结果自动入图片资产池，可被 PPT 使用（标"AI 生成"）。
7. 导出 PPTX。

**第一阶段最小闭环（对应验收）**：
```
选项目 → 生成 12 页图文底稿(页级卡) → 每页看缺什么图 
  → 从图片池选图填槽 / 缺图页发起生图(提示词确认→单张→入池→回填) 
  → 导出 PPTX
```
**生图第一阶段只做**：提示词确认 + **单张**生成 + 入池 + 回填。（多张变体/忠实度旋钮进中期——受 n=1、无 strength 卡点约束）

## 7. 验收问题（🔒 用户已给，作第一阶段 DoD）

1. 能从一个真实项目资料包生成一版 **13-20 页**（默认 20）图文底稿？
