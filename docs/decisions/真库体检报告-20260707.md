## 三、口径校验(出报告前自证,防"全丢"式误报重演)
- **base 用运行时 `expanduser(~)` 展开**,不手打用户名(手打导致本次一度误判"两个库")。
- **空根 54 条**:abs_of 回退 UPLOADS_ROOT(override 到本库自己的 uploads)→ **54/54 物理在位**(抽验 EXISTS)。
- **绝对根 153 条**:abs_of 用 `c:\仓库-00` 拼 stored_path → 该根空 → 全 missing,明细路径可人工核对(如 `C:\仓库-00\01_项目资料\...pdf`)。
- **孤儿独立重算**:不信任封装边界,显式 walk uploads + 逐个比 known_abs → orphan=0。**已排除系统目录 `_assets/_trash/_done/_failed`**:目录3 下 4722 个文件全在 `_assets/`(解析派生缓存,非用户文件),正确跳过,故 orphan=0 成立而非漏算。uploads 用户文件 54 = 空根 active 记录 54,精确对齐。
- **同一物理文件判定**:用 `os.stat` 的 st_ino+st_dev(金标准),非路径字符串/filecmp。
