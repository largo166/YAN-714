## 二、存疑锚点(4条,请逐条确认后我改蓝本留痕)

### 存疑① · "16 域认知卡" ↔ 实际是"module 维度 + 任务书16字段"
- **蓝本措辞**:多处称"16 域认知卡"/"16 域装建筑判断"(§2、§6 项目DNA)。
- **代码实际**:`ProjectCognition` 是 **`module` 维度**(brief/site/program/case/concept…,`models.py:303`),字段注释写"任务书**16字段**"(`models.py` fields_json 注释)。即:**是"若干模块,每模块内有受控字段(如任务书16字段)",不是"16 个认知域"**。
- **性质**:概念错位(第①类:说法与 schema 不符)。战略不受影响,但"16域"这个反复出现的口号与库结构对不上,后续 P5 实现会踩。
- **建议**:蓝本统一改为"模块化认知卡(module,如任务书16字段)",或你确认"16域"是产品叙事层的另起概念(与 schema 解耦)。**等你定。**

### 存疑② · D2"健康格读缓存" —— 缓存源(useBoardLive 健康分)不存在

- **性质**:第②类("已有"其实没有)。D2 是**纯增量**,不是"接现成缓存"——需新建"项目级健康缓存"数据通路(后端 `/projects/{id}/health` 读缓存 + 前端 live 补健康字段)。
- **连带**:蓝本 API `GET /api/projects/{id}/health`(**按项目**)与现有 `/api/knowledge/health`(**全库**)**粒度不同**,是两个端点,不是"已有"。
