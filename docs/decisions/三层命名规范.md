# 已批决议 · ROM-AI 三层命名规范（2026-07-07 定稿待微调）

> 裁决落档铁律:本文档是执行依据。规范本身已批为「产品级方法论资产」;但**具体执行动作**(改名/去重/归属/改 ingest 管线)仍需逐块确认——批"规范"≠批"立即全量执行"。
> 一句话:建筑项目的命名坐标系(城市-甲方-地块-阶段-类型)是行业最成熟的知识结构,ROM-AI 不发明分类法,只把行业已有秩序写进代码。这是区别于通用知识库产品的护城河。
> 铁律:**名字即元数据**——stored_path 拍平后,文件名是唯一归属线索。命名不是整洁癖,是数据可信度第一道防线。

## 第 1 层 · 项目命名:`城市-甲方-案名/地块` 三段式
示例:`杭州-保利-云城瑧悦南地块` / `石家庄-保利-市庄路` / `济南-保利-长岭山E15` / `哈尔滨-中艺-群力多地块` / `襄阳-国投-建华望府`
规则:
- **城市**:地级市标准名(不带区县;"石家庄长安区"→"石家庄",区县进字段不进名)。
- **甲方**:简称(保利/万科/金茂/新希望),**与甲方画像聚合字段共用同一份归一词典**(一处维护两处受益)。
- **案名/地块**:优先地块名/正式案名;投标期无案名用地块路名。
- **状态(投标/中标/深化/竣工)、年份 → 进 `ProjectCognition` 结构化字段,不进名字。名字管身份,字段管属性。**
- B 守卫升级:项目名不匹配 `城市-甲方-xxx` 模式 → 向导**标黄提示建议名(不拦死)**。

## 第 2 层 · 文件入库命名:`[项目短码]_[阶段]_[类型]_[语义名]_[版本]`
示例:`HZYC_TB_文本_台坞庭方案说明_v3.pdf` / `SJZ市庄_SS_图纸_一期总平_20260315.dwg`
取值域(建筑行业收敛):
- **阶段**:TB投标 / FA方案 / CS初设 / SS施工图 / XC现场 / JF交付
- **类型**:文本 / 图纸 / 效果图 / 模型 / 会议 / 甲方来文 / 规范 / 造价 / 照片
- **版本**:v数字 / 日期 / final(final 只许一个)
- **执行落点 = ingest 管线,不指望人手改名**:入库时**保留原始文件名(存字段,永不丢)**,同时生成规范名+结构化标签。人只确认,机器改名。

## 第 3 层 · 归属识别:词典匹配 → LLM 建议 → 人工确认
1. **项目词典匹配(确定性,先跑)**:每项目维护关键词组(`市庄路: [市庄路,振三街,长安天曜,华药]`、`襄阳: [襄阳,建华望府,国投]`)。命中即高置信归属。经验:469 存量文件七成含城市/案名,一轮扫掉大头。
2. **LLM 批量建议(处理剩余)**:文件名含糊的(01.JPG/DJI_xxxx)读内容/EXIF 出低置信建议,**只进建议表**。
3. **人工批量确认**:按"建议归属"分组给用户,**按组批不逐个批**。机器递笔,人签字(同甲方画像的抽取-建议-确认哲学)。
- **时间戳重复副本(_030610 后缀)先去重合并**:同名+同哈希只留一份,副本软删记日志。真实规模缩掉一半再谈归属。

## 产品化落点(Phase 2)
- 第1层 → B 守卫(建议名提示)。
- 第2层 → ingest 管线(自动规范名 + 保留原名字段)。
- 第3层词典表 → 建库,即归一词典第一个落地形态。
