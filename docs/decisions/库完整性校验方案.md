> 队列既定项,不再问直接出。这是真库清洗的前置、数据操作铁律第0条的自动化落地、也是 ROM-AI「库健康」产品功能雏形。

## 一、核心:四态体检
按**真实落盘口径**核验每条 ProjectFile 的物理文件——口径就用这次踩坑摸清的:
- `storage_root` 非空 → 物理路径 = `storage_root / stored_path`(stored_path 为绝对则直接用);
- `storage_root` 空 → 回退 `DATA_DIR/uploads / stored_path`。

对每条记录判定,分四态出报告:
| 态 | 判定 | 含义 |
|---|---|---|
| ✅ 记录在·文件在 | 物理文件 exists | 健康 |
| ⚠️ 记录在·文件丢 | 记录有、物理文件不存在 | 零星文件丢失 |
| 🔵 文件在·记录无(孤儿) | 扫 storage_root/uploads 下有物理文件、但无对应活动记录 | 孤儿文件(入库中断/记录被删) |
| 🔴 **root 脱节(第四态,新增)** | 某 storage_root 指向的目录**不存在或为空**,而库里有指向它的活动记录 | **整个仓库根迁走/丢失**(7-06 换根即此) |

**第四态与零星丢失分开报**:root 脱节是**系统性**的(一次丢一整根),要一眼看出"仓库根迁走了",不淹没在成百上千条"文件丢"里。报告先按 storage_root 分组,每组先判 root 是否脱节(目录级),脱节则整组标 🔴 并汇总"该根 N 条记录全部受影响",不再逐条报 ⚠️。

## 六、附:新 backlog——仓库根迁移向导
用户改 `repository_root_path` 时,检测旧根下有受管文件的,引导三选一:
- **迁移文件到新根**(把旧根物理文件搬到新根,更新 stored_path/storage_root);
- **保留旧根双库**(旧根记录仍指旧根,新入库走新根);
- **仅换根**(明确警告:旧根文件将访问不到=这次踩的坑)。
