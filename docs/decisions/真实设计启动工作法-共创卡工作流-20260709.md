# 真实设计启动工作法 · 共创卡工作流(2026-07-09 已批·产品原则)

> 对外名:**真实设计启动工作法**(Design Kickoff Co-Creation);内部名:**共创卡工作流**。
> 一句话:ROM-AI 不先替设计师下判断,而先把真实设计过程里的矛盾/可能性/案例启发/决策分叉结构化,
> 让设计师更快进入高质量判断,并把判断沉淀为可复用项目资产。
> 最短定义:基于项目资料识别关键未决分支,以案例/设计模式启发多路径,推荐押注并让用户确认,
> 最终把设计判断写回项目认知脊椎,转化为报告/PPT/方案修改动作。

## 底层链(所有"项目启动/方案共创/投标研判/PPT 生成"共用)
```
资料证据 → 问题地图 → 案例启发 → 方案发散 → 推荐押注 → 用户确认 → 认知写回 →(转生产)
```

## 七条产品原则
1. 不问常识,只问分叉。
2. 不直接裁决,先提供启发。
3. 不裸问问题,必须生成共创卡(证据/问题本质/设计模式或案例/2-3 方向/推荐押注/反方风险/待确认判断/写回字段)。
4. 不围绕概念复读,必须跨决策线推进(同一概念最多两轮,超过切场地→产品→总图→成本→汇报)。
5. 不只总结资料,必须指向设计动作。
6. 不让判断散在聊天里,必须写回认知脊椎(A1-A8)。
7. 不做通用 AI 聊天,必须服务真实设计启动。

## 承重墙判断(研发核心提出,负责人采纳)——为什么不能现在全做
整套工作流的第一步(把资料自动拆成 事实/常识/关键分叉)与第三步(真实案例启发)**踩的是模型建筑判断力天花板**——
而营地 C-P0 盲评已用真金白银证伪:judge 的"不专业"是模型建筑判断能力不够,不是机制能补。
"15m 支路是伤口还是价值放大器"这个分类本身就是最高级的建筑判断;AI 能自动分对 = 它已具备它其实不具备的能力。
故:**方法对,"现在就全做"错。** 拆两层落地。

## 两层落地(已批范围 = 仅第一层)

### 第一层:能立刻做(纯结构,不吃建筑判断力)—— 本次批准
1. 资料读取(已有)+ 图片资产/OCR/页码(已有);
2. **共创卡结构化容器 + 认知写回通路**(七字段 UI 壳 + 写回认知脊椎);
3. **判断 → PPT 大纲骨架**(只到页标题 + 该页要讲的判断,不出成品页)。

### 第二层:必须等模型/语料(吃建筑判断力,受 C-P0 裁决约束)—— 暂不做
1. 自动识别关键分叉(第一步全自动版);
2. 真实项目案例启发(第三步具体案例);
3. AI 主动推荐押注的质量(第五步"推荐"部分)。

## 四条红线(2026-07-09 负责人定,violation 即回滚)
1. **第一步永远"AI 摊草稿、人圈选定稿"**——全自动识别分叉不得合入。问题地图质量由人保证,AI 只做"把资料摊开供快速圈选"的降负载。
2. **写回必须"改写后确认"**——不改文本不允许写 `status: confirmed`(铁律级)。防用户点头 AI 的话 → 认知脊椎被 AI 意见污染。认知脊椎只装人的已审定判断(gather_cognition 只注入 confirmed)。
3. **案例启发只用抽象设计模式**(边界开放腹地私密/道路从割裂到界面/小地块城市触点大地块居住主体/首开展示即未来交付资产…)——**具体项目类比(太古里/新天地…)一律标"待人工核实"**,不假装懂真实案例数据。
4. **容器即语料采集器**——共创卡管道的首要产出是人填的高质量专业语料(分叉/案例/押注判断),这些样本直接服务 C-P0 盲评门解封条件。**此条是本次放行"管道层"的正当性来源;严禁把"管道已通"误读为"判断层可以顺手上"。**

## 解封条件(第二层上线的唯一通道,写死)
**人填共创卡 ≥ N 份 + 盲评通过,双门齐过**,才逐项接自动分叉/案例/AI 推荐押注。
- N:研发按采集速度提议,负责人定(见开工单)。
- 与营地 C-P0 裁决一致:本决议**不是解封营地线**,是让"容器"先通、人往里填、样本反哺盲评门。

## 转生产(第七步,近期只到骨架)
共创判断 → PPT 大纲骨架 / 报告结构骨架(页标题+该页判断);**成品页内容质量吃建筑判断力,属第二层,不承诺**。
骨架是结构(AI 长板),成品是判断(AI 短板)。
