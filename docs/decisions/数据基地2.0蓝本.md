## 1. 一句话判断
功能会被追平,认知追不平。 Linkly 已证实同样有对话、知识库、检索——ROM-AI 与它的差距不在"有没有判断层",而在判断层里装的是不是建筑设计的判断。数据基地 2.0 的全部战略,压在一件事上:把管道能力(检索/大纲/供给)内化为地基,把力气全投到认知层的行业纵深——这是唯一追不平的东西。

## 2. 战略前提重估(v2 核心变化)
| 维度 | v1 判断(已失效) | v2 实证结论 |
|---|---|---|
| Linkly 定位 | 纯管道,无对话无判断 | 检索+对话一体机,有 Chatbot+内建嵌入 |
| ROM-AI 优势 | "有判断层"是护城河 | 判断层已被追平,护城河收窄为认知层的建筑纵深 |
| 差异化叙事 | "我功能比它多" | "我的判断比任何通用工具更懂建筑" |
| 唯一结构性差异 | 模糊 | get_cognition——外部 AI 通过 MCP 取回建筑项目的判断,而非文档 |

这个重估是聚焦令:停止用功能级差异说事(会被追平),把每分力气压到"16 域认知卡装的建筑判断"上——就像投标,设备参数人人抄得到,评委记住的是你对这块地的独家理解。

## 3. 产品叙事:四段递进
进得来 → 信得过 → 找得到 → 用得上。
前两段已用四个包打完(A语义+守卫解决进得来;三 hotfix+体检解决信得过)。本蓝本主攻第三段"找得到",第四段"用得上"是认知供给,是护城河的工程兑现,归 Phase 2。一句定义:把散乱文件夹变成可检索、可归档、可体检、可被 AI 调用的建筑项目资产——"可体检"是四个包的信任成本换来的,写进定义不可删。

## 4. 目标架构(真实版,纠偏)
```
ROM-AI.exe(PyInstaller 单文件,keyless)
└─ pywebview 窗口(WebView2)
   └─ FastAPI 单进程 · 127.0.0.1:动态端口
      ├─ 同源托管 dist/(React+Vite+Tailwind,海天OS)
      ├─ routers/ staging(A语义)·ingest(五段+SSE)·knowledge(stats/search/health)
      │            project_files·settings·[新增]outlines·versions·archive
      ├─ 核心: ingest.py 编排 · project_naming.py 守卫
      │        storage_probe.py 路径唯一口径(委托 uploads.abs_of)
      │        parsing.py(PDF/DOCX/PPTX/XLSX/MD/TXT)· ocr.py(RapidOCR 本地,已上线)
      │        retrieval.py(FTS5+BM25 排序,已完整)
      ├─ SQLite rom_ai.db + FTS5(单库,alembic)
      └─ [P5] MCP server:同进程 /mcp 路由,复用 service 层
```
纠偏声明:外部方案的 3000/8000/8766/8788 多服务架构不存在。其所有"服务间转发"在本架构下是同进程模块调用,零网络开销——这是单机产品的正确形态,不是缺陷。

## 8. 数据库增量 DDL(按阶段)
```sql
-- P1 · project_files 补列(吸收 Linkly 机制)
ALTER TABLE project_files ADD COLUMN content_hash TEXT;        -- 内容级指纹,改名可识别
ALTER TABLE project_files ADD COLUMN storage_mode TEXT NOT NULL DEFAULT 'warehouse';
ALTER TABLE project_files ADD COLUMN retry_at INTEGER;          -- 可恢复失败退避,跨重启
ALTER TABLE project_files ADD COLUMN extract_truncated INTEGER NOT NULL DEFAULT 0;

-- P0 · 体检报告(评分制,权重定稿前 score 留 NULL)
CREATE TABLE health_reports(
  id INTEGER PRIMARY KEY, project_id INTEGER, run_at INTEGER NOT NULL,
  score INTEGER, metrics TEXT NOT NULL, findings TEXT NOT NULL);

-- P2 · 版本链
CREATE TABLE version_groups(
  id INTEGER PRIMARY KEY, project_id INTEGER NOT NULL REFERENCES projects(id),
  label TEXT NOT NULL, recommended_file_id INTEGER, confirmed_file_id INTEGER,
  status TEXT NOT NULL DEFAULT 'open');   -- open|confirmed|conflict
CREATE TABLE version_members(
  group_id INTEGER, file_id INTEGER, signals TEXT NOT NULL, rank INTEGER,
  PRIMARY KEY(group_id,file_id));

-- P3 · 审计回滚
CREATE TABLE archive_actions(
  id INTEGER PRIMARY KEY, job_id INTEGER NOT NULL, file_id INTEGER,
  action_type TEXT NOT NULL, old_path TEXT, new_path TEXT, old_name TEXT, new_name TEXT,
  confidence REAL, reason TEXT, approved INTEGER DEFAULT 0, executed INTEGER DEFAULT 0,
  executed_at INTEGER);

-- P4 · 大纲(渐进披露地基)
CREATE TABLE outlines(
  id INTEGER PRIMARY KEY, doc_id INTEGER REFERENCES knowledge_documents(id),
  parent_id INTEGER, ord INTEGER, level INTEGER, title TEXT NOT NULL,
  page_start INTEGER, page_end INTEGER, quality TEXT NOT NULL DEFAULT 'none');
```

## 11. 风险与边界(实弹版,每条带出处)
1. 数据操作铁律第0条:动库先验"活库+文件在"——死库事故换来,rollback/清洗一体适用;
2. reveal 路径只走 storage_probe,禁第二份拼接——口径分叉是三个 hotfix 病根;
3. 版本智能只建议,confirmed 必须人签字——错定版比不定版伤害大;
4. /health 首页格读缓存,实时探测只在 run 时——防千篇库拖慢冷启动;
5. P2 向量前置闸:先 grep 全库 embedding/vector/pgvector 残骸(你记忆里有过 pgvector/GBrain 探索),出核查表,定续建或清除——防第二次口径分叉;向量选型采信 Qwen3-Embedding-0.6B,但数百 MB 打进 keyless 单 exe 的体积成本须正面拍板,不顺手带过;
6. MCP 公网隧道 = 永久禁止项:违"数据不出本机",保利投标资料涉密,任何公网暴露是事故源——只走本机/局域网,与你事务所管控图纸外流同一纪律;
7. AI 置信度<0.6 进未归类,宁可未归类不许错归类(已落档);原始文件名永不丢弃(铁律);
8. 所有 apply 过 archive_actions,先 approved 后 executed;
9. @ 语法与过滤器共用一条查询通路,禁双源;
10. 本文档是活文档蓝本,与 docs/decisions/ 冲突以决议为准;发现过时按证据结案通则修订留痕。
