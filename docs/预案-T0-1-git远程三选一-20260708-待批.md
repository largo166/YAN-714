## 方案A · 私有 GitHub

| 维度 | 评估 |
|---|---|
| 异地容灾 | ✅ 最强(微软数据中心,机器烧了也在) |
| 涉密面 | ⚠️ 代码+决议文档出境到第三方云。**投标资料本身不在 git 里**(.gitignore 已排 data//uploads),但 docs/ 里有甲方名/项目名(如"济南长岭山""石家庄市庄")——需接受"项目元信息在私有云"这个事实 |
| 网络 | ⚠️ 国内访问时好时坏,push 可能要代理 |
| 成本/运维 | 免费私有仓,零运维 |
| 附加值 | ✅ 后续可挂轻量 CI、可从任何机器 clone(冷迁移演习的天然载体) |

```powershell
# 前置:gh auth login(或已有 SSH key)
gh repo create ROM-AI --private --source . --remote origin
git push -u origin --all      # 32 个分支全推
git push origin --tags
```

## 方案B · Gitee 私有仓

| 维度 | 评估 |
|---|---|
| 异地容灾 | ✅ 强(国内云) |
| 涉密面 | ⚠️ 同 A(第三方云,国内主体——按你对"数据在谁手里"的偏好定) |
| 网络 | ✅ 国内快且稳,无代理需求 |
| 成本/运维 | 免费私有仓(单仓 ≤500MB,当前裸仓约几十 MB,富余);零运维 |
| 附加值 | 可 CI;从任何国内机器 clone 快 |

```powershell
# 前置:gitee.com 建空私有仓 ROM-AI(网页操作),配 SSH key
git remote add origin git@gitee.com:<你的账号>/ROM-AI.git
git push -u origin --all
git push origin --tags
```

## 方案C · 本机第二块盘 bare repo(或 NAS/移动硬盘)

| 维度 | 评估 |
|---|---|
| 异地容灾 | ⚠️ 弱——同机第二块盘只防"单盘故障",不防整机(火/盗/勒索);放 NAS/移动硬盘可升半级 |
| 涉密面 | ✅ 零外泄,数据不出屋 |
| 网络 | ✅ 无依赖,push 秒级 |
| 成本/运维 | 零成本;**但备份纪律靠自觉**(忘 push=没备份,无云端兜底) |
| 附加值 | 无 CI/无异地 clone;冷迁移演习要靠拷盘 |

```powershell
# 例:D 盘(或 NAS 映射盘/移动硬盘) 建 bare 仓
git init --bare "D:\ROM-AI-backup\ROM-AI.git"
git remote add origin "D:\ROM-AI-backup\ROM-AI.git"
git push -u origin --all
git push origin --tags
```

## 组合建议(供参考,你定)

**C + (A 或 B) 双远程**是常见稳妥解:C 秒级日常 push(零涉密顾虑),A/B 作异地兜底(低频推,接受元信息在云)。git 原生支持多 remote:
```powershell
git remote add backup "D:\ROM-AI-backup\ROM-AI.git"   # C 作 backup
git remote add origin git@gitee.com:<账号>/ROM-AI.git  # B 作 origin
# 日常:git push backup --all(秒级);周期:git push origin --all(异地)
```
