## 块 1｜入库语义 A：选目录后加"项目确认"屏

### 后端 `app/routers/staging.py`（改分组逻辑，加"一级子目录展开"）
- 现状：选一个目录 → `_iter_files` 递归**全部文件进一个组**，组名=所选目录名。
- 改：`build_staging` 增加一层判断——
  - 若所选目录**含成型子目录结构**（有一级子目录、且子目录里有文件）→ **每个一级子目录 = 一个 group**（project_hint=子目录名），不再把父目录整个当一个项目；父目录下的散落文件(直属)单独归"(根目录散файлы)"组或忽略（待定，见待决①）。
  - 若所选目录**本身是叶子**（直接是文件、无子项目结构）→ 整个目录作为一个 group（现有行为），project_hint=该目录名。
- `StagingOut`/`StagingGroupOut` 复用（已有 source_dir/project_hint/project_id/files）——A 天然就是"多 group"，前端已能渲染多组。**加字段**：`group.is_subdir_of_selected: bool`（标记这是"父目录下的一级子项目"，供前端"项目确认"屏区分展示）+ 顶层返回 `selection_mode: 'multi_project' | 'single_project'`（供前端选默认勾选/单项目选项）。

## 块 2｜名字守卫 B：后端 ingest 入口前置校验（不只前端，防别的入口绕过）

### 新增 `app/project_naming.py`（或并入 project_files）——纯函数，可被 ingest/inbox/API 共用
- `reject_as_project(path) -> str|None`：**拒绝**（返回错误文案）——
  - 仓库根本身（== settings.repository_root_path）
  - 系统/用户特殊目录：desktop / downloads / documents / c:\users\* 顶层 / 盘符根
  - 返回明确错误"请选择项目文件夹或包含项目的父目录"
- `warn_as_project(name) -> str|None`：**警示**（返回提示文案，不拦）——
  - 编号前缀模式：`^\d+[_\-]`（01_、02-…）
  - 通用词单独成名：`项目资料`/`基础资料`/`资料`/`文件`/`素材` 等
  - 提示"这看起来是项目内部目录，确认作为项目？"
- **落点**：ingest `start_ingest` / `_ingest_worker` 建项前调 `reject_as_project`——命中即整批拒绝并回明确错误（不静默建脏项目）；`warn` 只在 staging 返回给前端标黄，不在后端拦。
- staging 也调这两个函数，把 reject/warn 结果放进 `StagingGroupOut`（加字段 `reject_reason?: str` / `warn_reason?: str`），前端据此拦/标黄。
