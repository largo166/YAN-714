# 现状契约 · b1 一键清理+自动入库(三步向导第0步产物)

> 工单强制前置(先读后写)。2026-07-06 三路只读审计(backend 行号级证据)。**结论落档后方可写码。**
> 一句话:清理链路红线安全、契约干净,可直接接向导;**但"自动入库"与"建仓库"两处后端能力不足,按预授权降级,不新建管线。**

## 一、清理三端点契约(workspace.py)

| 项 | 事实 | 证据 |
|---|---|---|
| **apply 入参** | 收 `rel_paths: list[str]` + `confirm`;根目录固定取 DB 全局 `cfg.workspace_path`,**不支持按请求指定仓库** | routers/workspace.py:74-85 |
| **部分执行** | ✅ 支持——`for rel in rel_paths` 只移传入子集,无隐式全量兜底(传空=移 0 个) | workspace.py:164,175 |
| **隔离区** | `root/_ROMAI_CLEANUP_QUARANTINE/<YYYYMMDD-HHMMSS>/`,保留 rel 目录结构;无保留期、无自动删除 | workspace.py:20,170-172,185 |
| **恢复** | restore 读该时间戳 manifest.json → shutil.move 还原 | workspace.py:206-222 |
| **🔴 红线核验** | **未发现真删**:全文 grep remove/unlink/rmtree/rmdir 零匹配;apply/restore 全程 `shutil.move`。"只移入隔离区·永不删除"**代码层属实,⑧硬停不触发** | workspace.py 零匹配 |

**已知脆弱点(非红线,记录在案)**:
- 同一秒内两次 apply 共用同一时间戳目录 + manifest 覆盖写(exist_ok=True :172, :200)→ 后批覆盖前批 restore 记录。
- shutil.move 未包 try(:184-187)→ Windows 文件占用抛 OSError 会中断整批且 manifest 未落盘 → API restore 找不回。
- **向导执行步应对策**:执行结果卡如实显示"成功/跳过/失败"三计数;失败项明示"未落盘、需人工在隔离区查",不伪装全成功(三态诚实)。

## 二、配置归一(app_settings 三列)

- 三个路径**存同一张表 app_settings(id=1)**,但**端点+语义三分叉**:
  - `workspace_path` ← POST /api/workspace/config(清理扫描根,**零校验**)
  - `repository_root_path` ← PUT /api/settings(受管仓库落盘根,**校验最严**:绝对/存在/目录/非symlink/可写探针)
  - `inbox_root_path` ← POST /api/inbox/config(收件箱监听根,中等校验:is_dir)
- b4 设置浮层(SettingsOverlay.tsx)= 单入口但**扇出三写**(:56/61/65/69)。
- **建目录能力:无**。filesystem.py 只有只读 list-dir(文件头铁律:绝不创建/移动/删除);validate_repository_root 在路径不存在时反而提示用户去资源管理器自建。全仓 mkdir 均为内部落盘,无任意路径建目录端点。

**向导配置归一决策**:
- 向导第一步的"仓库"= **workspace_path**(清理作用于此,语义一致)。读写复用 `workspaceConfig` + `workspaceStatus`,**不持私有副本**(工单裁决)。
- 顺带补齐:向导第一步写入前做**前端存在性校验**(list-dir 探测),弥补 workspace/config 后端零校验的缺口——不改后端,前端把关。
- **"未配置→创建新仓库目录"降级**(预授权):后端无 mkdir 端点,新建目录=新管线踩红线。向导第一步改为**"选择已有目录"**(系统选择器/路径输入 + list-dir 校验存在),文案明示"请选择已存在的文件夹;新建请在资源管理器完成"。**不新建 mkdir 管线。**

## 三、自动入库(§4)——判定:降级

- **唯一目录级批量入库** = inbox.scan_once(POST /api/inbox/scan),但**绑死单一 inbox_root_path + 写死"收件箱"项目 + 搬动源文件**(copy 进受管根、原件移 _done),不能对任意目录/项目触发。旧 batch-ingest 已删。
- 清理落到 `workspace_path` ≠ inbox 监听的 `inbox_root_path`;**清理产物不会被 inbox 自动收**。二者无自动接力。
- inbox 60s 轮询**仅桌面壳(launcher)有**,dev uvicorn / Web 态无任何自动扫描。

**自动入库决策(预授权降级,三态诚实)**:
- 清理落位后**不自动索引**(无通用端点,且复用 inbox 会带收件箱语义+搬源文件副作用,与向导冲突)。
- 结果卡显示 **"清理完成,待入库 N 篇" + 「一键入库」按钮**;点击走既有逐文件 `uploadProjectFile + indexProjectFile` 回环累加计数,完成后显示"已入库 N 篇"。
- **不做假自动**——工单§4 中性态优先级已明确高于流畅。

**幂等注意(影响测试残留清除)**:
- 同 ProjectFile 重复索引幂等(indexed_doc_id 守卫);FTS DELETE+INSERT 幂等。
- **非幂等点**:upload_file 端点不查重(project_files.py:198-234),重复上传同文件必新建 ProjectFile→新 KnowledgeDocument。测试残留须逐条 delete_document(连带删 FTS);ProjectFile 仅软删。
