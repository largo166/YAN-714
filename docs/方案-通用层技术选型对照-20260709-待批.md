## 二、真待批的两项选型

### 1. 报告出口 HTML→PDF(第4件的出口部分)
- 外部建议:WeasyPrint 或 Playwright 打印。
- **均不采纳,理由在打包形态**:
  - WeasyPrint 依赖 GTK/Pango 原生 DLL,Windows + PyInstaller onefile 下是知名打包坑;
  - Playwright 打印需携带整套 Chromium(数百 MB),与单文件桌面包体积/离线定位冲突。
- **我方推荐(待批)**:零新依赖路径——复用现有 `exporters.build_print_html`,出口走
  a) pywebview(Edge WebView2)打印到 PDF;降级 b) Edge headless `--print-to-pdf`(Windows 自带)。
  PPTX 出口继续升级现有 `exporters.build_pptx`(已在,非新建)。
- 风险:企业策略机上 Edge headless 可能受限 → 以 a) 为主路径。

### 2. 大纲/章节提取(第3件)——唯一的真缺口
- 证据:全后端 grep `get_toc|outline|bookmark` **零使用**;而 fitz/python-docx/python-pptx 均已在包。
- 成本:接口级(`fitz.get_toc()` / docx heading 样式 / pptx 页标题),不触检索心脏,纯加法。
- **建议(待批)**:进 P1 队列,位置排 P1-2 统一命名之后;大纲字段挂 parse 结果,
  "先看目录再读章节"的渐进披露编排自研(这半件属垂直层)。
