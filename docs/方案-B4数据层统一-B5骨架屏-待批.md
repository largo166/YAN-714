## 一、问题复述（B④ 根因）

五个 live hook 的加载模型分叉，是"数据过期 / 切项目闪跳 / 失败卡死 / 首屏暗拉"多个表象的同一根因：

| hook | 现状加载模型 | deps | reload 能力 | 失败态 |
|---|---|---|---|---|
| `useProjectLive` | ✅ active+id 重拉 | `[active, projectId]` | 随 deps 自动重拉 | 返回 `err`（4 请求全败才置） |
| `useCockpitLive` | ✅ active+gate+ver 重拉 | `[active, gate, dataVer]` | `sendBroadcast` 内 `dataVer++` | 各请求 allSettled，静默 |
| `useKnowledgeLive` | ❌ `loaded` flag 一次性 | `[active, loaded]` | **无** | 返回 `err`（主数据） |
| `useHubLive` | ❌ `loaded` flag 一次性 | `[active, loaded]` | 仅 `reloadMembers`（局部） | 返回 `errs[]` |
| `useSkillsLive` | ❌ `loaded` flag 一次性 | `[active, loaded]` | **无** | 返回 `err` |

**目标契约（统一到 useProjectLive/useCockpitLive 已验证的形态）：**
1. 加载时机吃 `active`，不可见不拉（A 组已把 SkillsLive 的硬编 `true` 修掉，契约已就位）。
2. 去 `loaded` 一次性闸，改为可重拉：数据源变更 / 用户主动刷新 / 失败重试都能再拉。
3. 每个 hook 暴露 `reload()`，失败态 UI 复用 AgentCamp 的重试范式。

## 二、B④ 逐 hook 具体改法

**统一改法骨架（三个 loaded-flag hook 通用）：** 去掉 `loaded` state 与 `if(!active||loaded)return` 闸，引入 `ver` 计数器驱动重拉，`reload = () => setVer(v=>v+1)`，effect deps 改 `[active, ver]`，`if(!active)return` 只挡不可见态（不再永久锁死）。

### ① useKnowledgeLive（`hooks/useKnowledgeLive.ts`）
- 删 `loaded`/`setLoaded`（:32,45）；`useState` 加 `ver=0`。
- 主 effect（:34-55）deps `[active, loaded]` → `[active, ver]`；去 `loaded` 判断，保留 `if(!active)return` + `alive` 守卫。
- 收件箱 effect（:58-71）现在 `if(!active||inbox)return` —— 改为受 `ver` 驱动同刷（`[active, ver]`，去 `inbox` 短路），保证 reload 时收件箱状态同步刷新。
- 返回值加 `reload: () => setVer(v=>v+1)`；`KnowledgeLive` 接口加 `reload: () => void`。

### ② useHubLive（`hooks/useHubLive.ts`）
- 已有 `memberVer`（局部重拉成员）——**推广为全量 `ver`**：删 `loaded`（:26,51），主 effect（:29-56）deps `[active, loaded]` → `[active, ver]`。
- `reloadMembers`（局部）保留（成员 CRUD 后轻量刷）；**新增** `reload()` 触发全量 `ver++`。
- `HubLive` 接口加 `reload: () => void`。

### ③ useSkillsLive（`hooks/useSkillsLive.ts`）
- 删 `loaded`（:23,26,33）；主 effect（:25-40）deps `[active, loaded]` → `[active, ver]`。
- 返回值加 `reload`；`SkillsLive` 接口加 `reload: () => void`。
- 注：技能目录相对静态，重拉频率低，但统一契约后失败可自救（当前失败=永久空）。

### ④ useProjectLive / useCockpitLive —— **不改加载模型**（已合契约）
- 二者已 active 重拉、有 ver 型刷新。仅 **补齐 `reload()` 显式暴露**（当前 project 靠 projectId 变化重拉、cockpit 靠 dataVer），供失败态"重试"按钮调用：
  - `useProjectLive`：加 `reload = () => setVer(v=>v+1)`，主 effect deps 加 `ver`（不动 `[active, projectId]` 语义，仅追加手动刷新入口）。
  - `useCockpitLive`：`dataVer` 已在，导出 `reload = () => setDataVer(v=>v+1)`。

### reload() 暴露方式（统一约定）
- 一律返回对象字段 `reload: () => void`（与 `projectBridge.reload` 命名一致）。
- 局部刷新（如 `reloadMembers`）保留其名，全量刷新统一叫 `reload`。

### 失败态 UI 落点（复用 AgentCamp 重试范式）
范式原型（`AgentCampBoard.tsx:284-288`）：
```tsx
{!d.busy && d.err && (
  <div className="text-sk-risk">执行失败:{d.err}
    <span className="ml-2.5 inline-block"><FlowBtn onClick={() => retry(id, d)}>重试</FlowBtn></span>
  </div>
)}
```
逐 board 落点：
- **KnowledgeBaseBoard.tsx:65**（`统计加载失败:{live.err}`）→ 尾部加 `<GhostButton onClick={live.reload}>重试</GhostButton>`。
- **HubBoard**（`errs[]` 显示处）→ 每条/整体加"重试"→ `live.reload`。
- **SkillLibraryPanel:50**（失败文案）→ 加"重试"→ `live.reload`。
- **ProjectCenterBoard.tsx**（A 组刚加的 `live.err` 行）→ 加"重试"→ `live.reload`。
- 统一按钮语汇：`GhostButton`（次级操作），文案「重试」。

## 三、B⑤ 骨架屏（SkeletonBlock）

### 组件设计
- 新增 `components/common/Skeleton.tsx`：`SkeletonBlock`（单条占位）+ `SkeletonText`（多行）。
- 灰阶脉冲复用已立的 `sk-pulse`（透明度呼吸，守晕动红线）——**不引入位移/扫光**。
- 用法：替换各 board 加载态的裸「…」；给 `StatBlock` 套 `min-height` 保尺寸，骨架与真数据等高，消 layout shift。

### 落点（把「…」换成骨架）
- **ProjectCenterBoard.tsx:56,60,61**（三个 StatBlock 的 `live.loading?'…'`）→ `<SkeletonBlock w=... />`。
- **KnowledgeBaseBoard.tsx:28**（148px 巨号 `live.loading?'…'`）→ 大号 SkeletonBlock（等高，防巨号跳动）。
- **SkillLibraryPanel:44** 纯文本占位 → 骨架卡。
- 切项目闪跳（ProjectCenterBoard）：保旧数据至新数据到位 or 骨架占位二选一——**推荐骨架**（更诚实：明确"在加载新项目"而非"旧项目数据还对"）。

### ★ 单列给你拍板：脉冲参数（晕动症红线）
以下是 SkeletonBlock 视觉参数，**请你定档**（我给推荐值，均在晕动红线内=纯透明度、无位移）：

## 四、影响面清单 & 回滚

### 受波及文件
**hook（5）**：useKnowledgeLive / useHubLive / useSkillsLive（改加载模型）；useProjectLive / useCockpitLive（仅加 reload 暴露）。
**board（4-5）**：KnowledgeBaseBoard / HubBoard / SkillLibraryPanel / ProjectCenterBoard（失败态加重试）；ProjectCenterBoard / KnowledgeBaseBoard（骨架屏）。
**common（新增 1）**：Skeleton.tsx。
**css**：若复用 sk-pulse=0 改动；若独立参数=globals.css +1 keyframe。

### 不波及（明确不碰）
- 锁版视觉面：开机影片/口令闸/五板构图/胶囊导航/1280×720 舞台度量+字号 token —— 全不碰。
- 后端：零改动（纯前端加载时机/UI）。
- useCockpitLive 门禁逻辑（gate/unlock/setup）：不碰，只加 reload 导出。

### 回归风险
- **中**：跨 3 hook 改加载模型，有"重复请求/请求风暴"风险（reload 被频繁触发）——需在组件测试里断言 reload 幂等、不叠加。
- StrictMode 双挂载：现有 `alive` 守卫保留，去 `loaded` 后需确认双挂载不产生双请求（useKnowledgeLive 收件箱 effect 尤其注意）。

### 验证方式（按 CLAUDE.md 选型）
- **状态逻辑**（reload 重拉、loaded 去除后的重复请求防护）→ **vitest 组件测试**（形态无关，扩 CleanupWizard 同款做法覆盖各 hook 的 reload 行为）。
- **失败态重试 UI** → 组件测试断言"失败→点重试→重新请求"。
- **骨架屏观感** → dist/打包形态截图人审（标 BUILD_ID）。

### 回滚方式
- 每个 hook 改动独立、可单独 revert（不互相依赖）。
- 建议实现时**一 hook 一 commit**（KnowledgeLive / HubLive / SkillsLive / reload 暴露 / Skeleton 组件 / 各 board 落点），任一出问题单独回滚，不牵连。
- Skeleton 是纯新增组件，删文件即回滚。

### 分期建议
- **Phase 1**：B④ 三 hook 契约统一 + reload 暴露 + 失败态重试（逻辑层，组件测试守卫）。
- **Phase 2**：B⑤ 骨架屏（你圈定脉冲参数后）。
- 两期分开，Phase 1 过了再做 Phase 2，避免一次改太大。
