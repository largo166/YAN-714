# 方案 · 共创营地改版:投标前期概念逻辑锻造链（2026-07-08 · 草案,只分析不改代码）

> 批复定位:营地不再按"技能市场 + Agent 外衣"扩,重设为**投标前期概念逻辑锻造链**,重点 concept → compete → judge → writer 闭环。
> 输入材料:六路审计营地篇 + `sharpness_chain_analysis.md`(锻造链原始定义)+ `camp_audit_design_thinking.md`(审计报告)+ `camp_moa_implementation_plan.md` + 营地技能系统地面真相(记忆)。
> 本方案纯分析,零代码改动;实施拆包待批,且排在蓝本主线路权之后。

## 一、诊断:营地现在是什么,为什么撑不住

**现状(代码实证):** 22 个技能平铺 5 类(skills.py:38-66 静态注册表),全部走 LLM 单发问答;4 张快捷卡 + 4 张 Agent 卡 + 9 条斜杠命令 + 命令面板;MoA 4 预设(仅 review 接了 UI);成果落 skill_results 表,单条展示。

**三个结构性问题:**
1. **平铺=无生产关系。** 22 个技能是 22 个并列按钮,任何技能的产出都不是另一个技能的输入。用户跑完"概念激发"得到 3-5 个方向,然后呢?没有然后——下一步靠用户自己想。审计原话:"这不是四个并列的问答按钮,这应该是一条生产线"(sharpness_chain_analysis §3.1),但代码里生产线不存在(锻造链不存在于代码——营地记忆确认)。
2. **单发问答=平庸产出。** concept 现 prompt="提出 3-5 个有设计叙事的概念方向"(skills.py:74)——正是分析文档批评的"从关键词联想不从矛盾长",产出"绿色生态/在地文化"式的壳。**单发问答结构上就产不出非共识**,因为没有"先摸红海、再锁张力"的前置弹药。
3. **Agent 外衣=假身份。** "方案领航员/对标研究员/文本起草官/节点督办官"四张 Agent 卡只是技能的别名(campCards.ts,skillId 指向同一批技能),没有独立记忆/状态/工作流——穿了外衣的按钮。审计另证:4 个协作 agent 里 2 个是 status=plan 桩。

**一句话:营地有 22 门火炮,没有一条弹药线。改版不是加炮,是建生产线。**

## 二、新定位:投标前期概念逻辑锻造链

**定义:** 从"项目条件+红海认知"出发,经四道工序把概念逻辑从平庸逼到非共识,产物是一句能写进标书的独占性 main idea + 它的完整推导链。

**四道工序(采纳 sharpness_chain_analysis 的重定义,方向从"生成"反转为"消除平庸"):**

| 工序 | 现 prompt(单发问答) | 锻造链定义(链式工序) | 消除什么平庸 |
|---|---|---|---|
| **① compete 测红海** | "找类比项目做对标分析" | "这类项目+这个甲方,90% 投标会提哪 5 个概念?→标'会撞车,不许用';同行普遍忽略的盲区是什么?" | 不知道同行会做什么的盲目 |
| **② concept 逼非共识** | "提出 3-5 个概念方向" | 吃①的红海清单:"本项目哪条硬约束与甲方诉求/场地冲突(张力)?→针对每个张力给 1 条非共识概念逻辑:一句 main idea + 解了哪个张力 + 为什么评委没见过 + 最大风险" | 从关键词联想不从矛盾长的概念壳 |
| **③ judge 杀平庸** | "梳理节点挑风险"(现 judge 竟是督办!) | 吃②的候选:"逐条处决:撞①红海的杀、自嗨无张力支撑的杀、留 1 条最锋利的+补刀意见" | 撞车不自知/自嗨的伪差异化 |
| **④ writer 验独占** | "起草投标技术标设计说明" | 吃③的幸存者:"用一句话写出它的独占性表述——竞品套不上、评委没见过;写不出=概念不够锋利,**打回②重逼**" | 万能宣传语式模糊概念 |

**关键机制(区别于现状的三点):**
1. **链式传递:** 每道工序的结构化产出(JSON)自动成为下道工序的注入材料——不靠用户复制粘贴。
2. **可回退:** ④写不出独占句 → 打回②带着失败原因重逼(闭环不是流水线单向,是有质检门的回路)。
3. **认知脊椎复用:** ②的"张力"来自已确认认知(gather_cognition 只注入 confirmed 字段——现有机制,analysis.py:91),项目条件不是重新问用户,是从 A1-A8 认知模块拿。**锻造链是认知脊椎的第一个重度消费者。**

## 三、形态设计(营地板内,不加新板)

**主视图:锻造台(替换现在的"四张快捷卡+技能网格"首屏地位)**
- 一条横向四工位工序带:`红海 → 张力/非共识 → 处决 → 独占句`,每工位显示状态(空/进行中/有产出/被打回)。
- 点任一工位:左侧显示该工序的输入(上道产物+认知材料),右侧是产出卡;可单独重跑本工位(下游自动标"过期")。
- 一键"整链锻造":从①跑到④,SSE 逐工位进度(复用 ingest 的 SSE 模式,不新造)。
- 产物落 skill_results(现表,加 chain_id 关联同一次锻造——最小 DDL,一列)。
- **MoA 归位:** judge 工位天然适配 MoA(3 视角处决更狠)——把现有 compete_moa/concept_moa 暗预设接到对应工位的"会诊模式"开关,3 个 API-only 暗能力就地转正,不另立入口。

**保留但降级:**
- 22 技能网格收进"全部技能"抽屉(现 SkillLibraryPanel 已有,地位从主角降为工具箱)。
- 对话共创/斜杠命令保留(自由问答与锻造链并行,不互斥)。
- 会议纪要/清理跳板卡不动(它们本就不是营地主线)。

**judge 语义冲突处理:** 现 id=judge 是"节点督办"(督办属驾驶舱/协作语义,放营地本就错位)。改版时 judge 让位给锻造链的"平庸刺客",督办技能改 id(如 chase)移到协作语境或留技能抽屉——**具体迁移待实施时拍板,本方案只标记冲突**。

## 四、验收口径(设计即验收,提前写死)

**核心验收(盲评制,采纳分析文档 P1 建议):**
- 拿 3-5 个**真实过往投标**(已知中标概念),跑整链 vs 裸 ChatGPT 单问"给概念",产出并排盲评:锻造链的 main idea 是否更锋利(不撞红海/有张力支撑/有独占句)。**赢不了盲评就不值得上 UI——先验证 prompt 链,再建界面。**
- 秒表:整链(4 工位串行,3 工位可 MoA)一次 ≤ 5 分钟(单发 LLM ~30s×4 + MoA judge ~90s)。
- 三态:每工位 busy/err/产出三态齐;打回时下游过期标注诚实。

**实施分期建议(待批,均在蓝本路权之后):**
- **C-P0 prompt 链验证(零 UI):** 只写 4 个新 prompt + 链式注入脚本,后端 API 串通,拿真实投标盲评。**赢了才有 C-P1。**
- **C-P1 锻造台 UI:** 四工位带 + 整链 SSE + chain_id 落库。
- **C-P2 MoA 归位 + judge 语义迁移 + 三暗预设转正。**

## 五、明确不做
- 不做"更多 Agent 人设"(外衣已证伪);不加第六板;不动锁版视觉面(营地板内改版走小样先审)。

- C-P0 之前不写任何 UI 代码(盲评赢了才配 UI,输了改 prompt 再战——避免"界面先行掩盖产出平庸")。
