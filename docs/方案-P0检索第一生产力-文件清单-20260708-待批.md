## 一、后端改动(3 文件,~120 行;唯一新端点=reveal)

### 1. `backend/app/schemas.py` — hit 增补展示字段(纯加法)
- `KnowledgeHitOut` + `file_type: str = ""`、`doc_type: str = ""`、`updated_at: str = ""`、`project_id: int = 0`、`project_file_id: int = 0`(反查自 ProjectFile.indexed_doc_id,models.py:228;无关联=0)。
- `KnowledgeSearchIn` + `doc_type: Optional[str] = None`(类型过滤;None=不过滤)。
- **不改**既有字段与校验——旧调用方(营地RAG/紫黑)零感知。

### 2. `backend/app/routers/knowledge.py` — search 端点增强(不动 retrieval 核心)
- `search_documents`(:202):命中后**一次批量查询**补齐 hit 展示字段(document→file_type/type/updated_at;ProjectFile.indexed_doc_id 反查 project_id/file_id);按 `doc_type` 入参过滤(在 hits 层过滤,不改 FTS 查询——数据量 top_k≤50,内存过滤零成本)。
- **@语法解析不放后端**——前端解析成 project_id 传参(蓝本 §11.9"@语法与过滤器共用一条查询通路,禁双源":通路=现有 POST /search 的 project_id 参数)。

### 3. `backend/app/routers/project_files.py` — 新端点 reveal(蓝本 §9)
```
POST /api/projects/{pid}/files/{fid}/reveal
```
- 实现:取 ProjectFile → `storage_probe.resolve_physical(stored_path, storage_root)`(**唯一口径,蓝本铁条:禁第二份拼接**)→ 存在:`subprocess.Popen(['explorer', '/select,', str(path)])`(Windows 资源管理器定位到文件);不存在:404 带四态口径话术("文件缺失,建议跑库健康体检")。
- 安全边界:只接受库内记录 id,不接受任意路径入参(路径永远来自 DB+storage_probe,无用户可控路径)。
- knowledge 命中(无 project_file 关联的手工文档)无 reveal 按钮——**不伪造能力**。
