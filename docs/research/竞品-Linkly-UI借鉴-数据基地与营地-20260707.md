# Linkly UI → ROM-AI 可借鉴设计点（数据基地 + 共创营地）· 2026-07-07

> 输入:用户提供 Linkly AI 设置页 5 张真实截图(通用/AI/MCP/集成/知识库)。
> 这批截图信息量 >> 二进制分析,且**更正上一轮一个判断**(见下)。
> 纪律前置:**数据基地首屏是锁版纪念碑构图(巨号=真 stats.documents),冻结、绑晕动症红线**——
> Linkly 的界面只能给**局部组件/次级视图**灵感,**不得改 ROM-AI 首屏构图**。凡涉视觉锁版面的借鉴,单独拍板。

## 〇、上一轮判断更正(活文档留痕)
- 上一轮我判"Linkly 不做对话/无 chat"——**错**。截图证实它有 **Chatbot + 对话模型设置(默认模型/回复语言/模型提供商)**,且内建嵌入模型。
- 更正后的 Linkly 全貌:它**既做检索供给(MCP/CLI),又做自带对话**——是"本地文档检索 + 对话"一体,不是纯管道。这反而让它和 ROM-AI 的**可比性更高**(都有对话+知识库+检索)。
- 另一硬情报:**嵌入模型 = Qwen3-Embedding-0.6B**(内建,装完自动下载,语义搜索用)。比我上轮猜的 bge-small 更具体、更适合中文——**P2 向量检索选型可直接采信这个**。

## 一、数据基地(KnowledgeBaseBoard)可借鉴点

### 🟢 D1 · 知识库"库卡片"信息模型(截图5,最直接可抄)
- **Linkly 做法**:知识库列表 = 极简卡片,一张卡三行:`库名(yan-001)` / `领域标签(建筑)` / `1 个文件夹 · 21 个文档`。右上角"卡片视图/列表视图"切换 + "+"新建。
- **ROM-AI 现状**:数据基地是**单一大字纪念碑**(全库 documents 巨号),**没有"按库/按项目分组"的中间粒度**——用户看不到"哪个项目多少文档"。
- **可借鉴**:在纪念碑**下方**(不动巨号)加一排/一栅**项目库卡**,每卡 `项目名 · 领域 · N文件夹·M文档`,点进看该项目资料。这补上 ROM-AI 缺的"库/项目粒度视图",且与"项目中心"呼应。
- **边界**:加在首屏下半区或次级视图,**不碰上半区巨号锁版**。是否上首屏、还是收进"查看全部"次级页,需拍板。

### 🟢 D2 · 独立"索引"状态视图(截图左导航"索引"是一级功能)
- **Linkly 做法**:"索引"是**独立一级页**(和文件夹/知识库/AI 平级),专门看索引进度/状态。
- **ROM-AI 现状**:索引完成率只是纪念碑旁一个小数字(`idxRate`),**没有"哪些文档已索引/失败/待OCR"的明细视图**。
- **可借鉴**:这正好接上**我们刚做的库健康体检**——把"索引状态 + 四态健康(ok/missing/orphan/root脱节)"合成一个**「库状态」次级视图**,而非藏在设置页按钮里。Linkly 把它提成一级,说明这是高频需求。
- **落点**:复用 `storage_probe`/`/health` 已有数据 + `knowledge/stats` 的 indexed/engine → 一个只读状态页。低成本、高价值。

### 🟡 D3 · 卡片/列表双视图切换(截图5右上)
- 小交互:知识库右上角"⊞ 卡片 / ☰ 列表"切换。ROM-AI 最近入库/类型带目前单一呈现。**优先级低**,D1 落地时顺带。

## 二、共创营地(AgentCampBoard)可借鉴点

### 🟢 C1 · AI 模型设置的"提供商 + 就绪态"卡片(截图2,最该抄的交互范式)
- **Linkly 做法**:模型提供商呈现为**卡片**:`[图标] Linkly Official [就绪] [2 模型] ○ [配置钮] [开关]`——一眼看清"哪个provider、就绪没、几个模型、开关状态"。下方"+ 自定义提供商"。嵌入模型单独一卡带"已就绪✓/已下载✓"状态。
- **ROM-AI 现状**:营地有 `ModelSelector.tsx`,但模型/provider 的**就绪态、可用性**呈现较弱(设置页只有 DeepSeek Key 一个 password 框 + 已配置/未配置 pill)。
- **可借鉴**:把 ROM-AI 的"AI 引擎配置"从**单框**升级为 **provider 卡片模型**:每个 provider 一张卡(DeepSeek/本地/自定义),显 `就绪/未配置` + 模型数 + 开关。这让"多模型/MoA 会诊"有了**配置载体**——ROM-AI 已有 MoA 暗能力(3个API-only专家),但没有让用户看清"哪些引擎就绪可参会"的 UI。C1 正好补这个。
- **边界**:营地/设置页交互升级,不涉锁版视觉面,ROI 高。

### 🟢 C2 · "回复语言"设置(截图2,小而精的产品决策)
- **Linkly 做法**:AI 设置里有**「回复语言」**:固定 AI 回复+会话标题语言,可选"跟随用户"(模型按你消息判断)。
- **ROM-AI 现状**:无此设置。设计事务所常需中英混合汇报,"固定回复语言/跟随"是真实需求。
- **可借鉴**:营地对话 + 会议纪要 + 研判,加一个"回复语言"偏好(跟随/中/英)。**极低成本**(prompt 加一句),体验提升明显。

### 🟡 C3 · "集成"页的引导式接入(截图4,战略呼应)
- **Linkly 做法**:"集成"页把 Claude Desktop/ChatGPT/Cursor/Claude Code/Gemini CLI/Dify 等**逐个列出**,每个给 MCP/CLI/Skill 三种接入引导。
- **ROM-AI 呼应**:这直接印证我上轮 **P3 MCP server** 判断——若 ROM-AI 做 MCP 对外供给,**这个"集成引导页"就是范式**:让用户把 ROM-AI 接进自己的 Claude Desktop。但这是**战略级、单独立项**,不在近期 UI 迭代。

### 🔴 不抄:MCP 公网隧道(截图3"远程访问/公网")
- Linkly 有"连接公网隧道"把本地 MCP 暴露公网。**ROM-AI 明确不做**——违背"本地优先/数据不出本机"命题,且设计事务所资料涉密,公网暴露是红线。

## 三、优先级建议(待批)
| 级 | 项 | 归属 | 成本 | 依据 |
|---|---|---|---|---|
| 🟢 高 | **C1 provider 卡片化** | 营地/设置 | 中 | 给 MoA 多引擎一个配置载体 |
| 🟢 高 | **D2 库状态次级视图** | 数据基地 | 低 | 复用已做的 /health,把索引+健康提成视图 |
| 🟢 高 | **C2 回复语言偏好** | 营地对话/纪要/研判 | 极低 | 中英汇报刚需 |
| 🟢 中 | **D1 项目库卡** | 数据基地下半区 | 中 | 补"项目粒度"视图;**碰首屏须拍板** |
| 🟡 低 | D3 双视图切换 | 数据基地 | 低 | D1 顺带 |

## 四、给 P2 向量检索的直接输入
- **选型采信 Linkly:Qwen3-Embedding-0.6B**(本地、中文强、装完自动下载)。若做 P2 语义检索,优先评估这个而非 bge-small。
- 体积:0.6B 量级模型约数百 MB,打进 ROM-AI 包体积影响需评估——**仍待你对包体积的容忍度拍板**。
