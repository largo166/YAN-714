# 外部产品研究 · 工作流启发（2026-07-09）

> **研究员定位**：建筑设计前期 AI 工作流 + 地产开发决策支持产品。
> **取证纪律**：每站区分【官网明确写了】/【我推断】/【对ROM-AI建议】三层；营销数字一律标"存疑"。四站均以 first-party 抓取为主，外部评测为辅。
> **研究对象**：sonix.ai（转写）、cove.inc（AI 原生事务所）、easymap.uk/layout（版式生成器）、krea.ai（实时创意）。

## 四站本质判断（一句话各一）

| 网站 | 本质 | ROM-AI 该学什么 / 不学什么 |
|---|---|---|
| **cove.inc** | 把"早期判断"从一次性交付物变成**贯穿全流程、可反复对测的结构化脊椎(pro forma)**；商业上已放弃卖软件、改卖服务 | **学**：判断底座方法论。**不学**：自动出方案/判决、云端常驻、事务所形态 |

## 对 ROM-AI 最有价值的 5 条启发（跨站提炼）

**1. 判断底座（cove）——最高价值，定义"文档工具→判断系统"的分水岭。**
在项目第一天建立结构化 `ProjectIntent = {规划条件·任务书诉求·经济目标·关键约束·已批裁决·溯源}`，让每份入库文档、每条裁决、每份汇报都能**回指并对测**它。ROM-AI 不算 pro forma 数学，只做"承载+溯源+前置报警+一键成报"。**这条同时吃下 sonix 的"决议时间线"和已有的裁决落档铁律。**

**2. 每条 AI 结论锚定原文（sonix）——human-confirmation 的可核对基座。**
抽取的每一项（决议/行动项/实体/约束）都挂 `{原句, 出处/时间点, 说话人}`，点结论可回跳原文。这是堵幻觉、守三态诚实的通用模板，成本低、收益横跨会议纪要+数据基地+项目中心。

**3. 结构化抽取→任务闭环（sonix）——把已建好的后端能力接上前端。**
会议 decisions→项目认知、action items→任务看板。**这直接命中前端审计 Top①②**：`listAssignments/taskResultToAssignments`、`extractModule/confirmCognition` 后端全备、前端无入口。

**4. 半自动排版骨架（easymap）——汇报出口最大缺口，且素材已就绪。**
"先排版后填图"：用带 `asset_type` 的占位骨架把"排版"与"选图"解耦。ROM-AI 已有 easymap 最缺的东西（真实资产池 + 类型标签），缺的只是画布/starter/换图 UI。**命中前端审计 Top⑥。**

**5. 参考图共创回路（krea）——投入产出比最高的图片能力借鉴。**
参考图→强度→变体扇出→择优入池，几乎零新基建嫁接现有 `generateImageFromAssets`，且天生把判断权做成"择优确认才入池"的闸门。
**契约提醒（核 `api.ts` 补）**：前端层 `generateImageFromAssets(projectId,prompt,refAssetIds,model,signal)` **未暴露 seed/strength/batch**——"变体扇出"须多次调用近似，"强度滑杆"需后端确认或 prompt 近似。

## 【特别节】半自动 PPT / 图文报告最小闭环（easymap × 现有资产池）

```
图文大纲 → 自动生成板式(starter) → 批量填图(from listAllAssets/asset_type)
        → 人工替换(点槽换图) → 导出(复用 skillResultPptxUrl / 加 PDF·PNG)
```

| 步 | 需要的数据（现有 API） | 新 UI | 验收 | 标签 |
|---|---|---|---|---|
| 1 大纲 | 复用现有"结构化大纲→pptx"结构 | 大纲编辑区（几段文字+每页图槽数） | 录入 N 段+声明图槽数落盘 | 需补 UI |
| 2 板式 | 无新数据（前端模板 JSON：槽位+图文比） | starter 选择器 + 画布（空占位，空态"点击选图"） | 选 starter 铺出对应占位，纸张/横竖正确 | 需补 UI |
| 3 批量填 | `listAllAssets`+`asset_type`+`assetThumbUrl`（**全在**） | **填图预览面板**+确认按钮 | 出预览(每格填哪张/来自哪项目)→可改→确认才落 | **需拍板**（预填+确认形态 + asset_type→槽位映射） |
| 4 换图 | `listAssets`/`assetThumbUrl`/`assetImageUrl`（**全在**） | 点槽→资产网格(按项目/类型筛)→替换 | 点格出网格选另一张即换，跨项目图带来源标识 | 需补 UI |
| 5 导出 | `skillResultPptxUrl`（**已可实现,接线**） | 导出按钮组+Undo/Clear | 排好图板导出 1 页 pptx 不错乱(先决)；PDF/PNG 次之；SVG 中期 | pptx 已可实现 / PDF·PNG 需补 UI / SVG 暂缓 |

**该抄该分（easymap 控件逐项）**：纸张 A3/A2/A1 **抄**+加 16:9 幻灯尺寸；横竖版**抄**；主题**分**（换事务所品牌模板非竞赛审美）；字体**抄形式**但中文优先；starter/占位/Undo **抄**；Batch Fill **抄意图分形态**（必须预填+确认，不静默铺满）；矢量导出 SVG **抄但排中期**。

## 各站六段拆解摘要

### sonix.ai
- **定位**：cloud-first 按量计费的转写工作台，服务法务/医疗/媒体/研究等"经不起转写出错"团队；提效降错交付，不做判断。
- **价值链**：音视频→STT+diarization+词级时间戳→浏览器内点词校对→LLM分析(摘要/章节/决议/行动项/实体/情感/主题,每条锚时间点+说话人+原句)→翻译字幕→跨文件问答(带引用)→可导出定稿+机构记忆层。
- **传导链**：阶段2选的词典→阶段3/4专名准确率→阶段5实体/决议抽取质量→跨文件问答。**一个词典决策一路传导到机构记忆的可信度**——同 ROM-AI"命名=数据可信度第一道防线"。
- **不学**：cloud-first / 多租户、silent auto-transcribe-everything、外部协作者强制建账号、情感打分驱动决策、"99% accuracy"单值夸大。

### cove.inc
- **两个故事（关键校正）**：前身 cove.tool（2017）是**真卖外部的 SaaS**（$36.6M 融资、15000+ 用户），如今重塑为"全球第一家 AI 原生建筑事务所"，Vitras.ai 改口为**纯内部引擎**（"not sold as standalone""Practice-led, Not Product-led"）。**ROM-AI 恰站在 cove 主动放弃的产品路上**。
- **价值链主线**：**pro forma 是脊椎**——Strategy 采集为锚→Feasibility 实时对测→Design 约束方案→Delivery 作为验收标尺。"nothing moves forward blind / tested against your pro forma" 反复出现。
- **核心可迁移点**：cove 没把可行性做成"报告交完归档"，而是**变成贯穿七阶段、可反复对测的结构化对象**。这是"文档工具→判断系统"的分水岭。
- **不学**：常驻后台自动分析出结论、自动出方案/容积率最优/可行性判决、云端法规库常驻、把 ROM-AI 往"决策引擎/卖服务事务所"带。

### easymap.uk/layout
- **定位**：browser SaaS，"一键读懂城市"——从 OSM 生成 18-30 种场地分析图，Portfolio Layout 只是出图链最后一环（把分析图排成 A1/A2/A3 图板）。
- **价值链**：场地图片/分析图→选纸张+starter+主题+字体→Batch Fill 批量填占位→点模块换图换字→Undo/Clear→导出 PDF/PNG/SVG(AI)。
- **上游→排版连接**：`Layered Axon`「Select 2-8 analyses to stack · order = stack order → GENERATE POSTER」，本质是"有序集合→版式"映射。
- **不学**：从 OSM 合成分析图（非资产驱动、非 local-first）、云端外拉、一键静默铺满/填满（违反预填+确认红线）、水印付费墙、竞赛审美主题。
- **证据边界**：Batch Fill 内部机制**站点无文字说明**，属【我推断】；外部评测经两轮 WebSearch 确认不存在（勿与无关的 easymap.one/easymapmaker.com 混淆）。

### krea.ai
- **定位**：自称"world's most powerful creative AI suite"，聚合 64+ 第三方模型+自有模型进一个订阅一块画布；面向创作者/设计师，卖回路不卖模型。
- **价值链**：文字/参考图/画布→实时渲染(<50ms, LCM 4步)/风格迁移(strength 20-80%)/发散变体→图片(4K)/变体网格/放大。
- **紧回路秘密**：**没有"生成"按钮**——反馈"at the speed of your hand, not at the speed of a progress bar"；技术上是 LCM 把几十步扩散压到 ≤4 步 + 连续推理。
- **不学（为何不盲做生图工具）**：多模型聚合/视频/3D/LoRA 训练=通用生成器陷阱（与已撤 T1-6 同向漂移）；云端实时=破 local-first；"无生成按钮连续静默出图"=撞"永不静默执行"红线。**它的护城河（模型聚合+云实时）恰是 ROM-AI 的反面**。

## 一句话总结（每站该学什么）

- **cove**：学"pro forma = 早期判断脊椎"方法论 → ROM-AI 的**判断底座 + 风险前置 + 一键成报**；不学自动判决与云端常驻。
- **sonix**：学"把转写变成可溯源、可问答、可复用的机构记忆"；不学 cloud-first 与静默全转。
- **easymap**：学"占位骨架 + 批量填 + 单点换 + 矢量导出"的半自动排版闭环，素材源换成本地资产池；不学合成图与静默铺满。
- **krea**：学"参考图→强度→变体→择优留痕"的共创回路，接现有 img2img；**坚决不学它的产品形态**（模型聚合+云实时=ROM-AI 反面）。

> **一句话贯穿四站**：四个对象不约而同指向同一件事——**ROM-AI 的护城河不是"更强的 AI 能力"，而是"本地数据 + 认知资产 + 建筑师主导判断"**。cove 自己退出产品路、sonix 只有企业版才承诺不训练你的数据、krea 消费级拿走你内容的永久授权——**它们的软肋恰好是 ROM-AI 的立身之本。借它们的工作流与交互回路，别借它们的产品形态。**
