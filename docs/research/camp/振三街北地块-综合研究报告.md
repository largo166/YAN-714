### 1.3 缺失资料的后果分析

| **市场调研/竞品分析** | 户型配比（107/129/125/126/108/155）的决策缺乏市场数据支撑，极有可能与目标客群需求错位。行业经验表明，"营销部的户型配比可能朝令夕改，导致设计院反复调整"——本项目6月26日一天内户型调整4次（107→125→126，新增108、155），正是这一模式的典型表现。 | 【事实】素材汇编§3.2、§7.1；行业标准§2.3 |

## 二、业主需求与方案推进过程优化点

### 2.1 从集团文件提取的甲方核心诉求

| 诉求类别 | 具体内容 | 文件来源 | 判断来源 |
|----------|---------|---------|---------|
| **上报门槛** | 必须包含：营销"一房一价"专项 + 成本适配专项分析 + 地库专项方案 + 首层拼合总平面方案；**未包含以上专项，不允许上会审议** | 集团文件§4.1 | 【事实】 |

| **方案比选** | 完整新开地块或楼栋≥5栋的组团，须做**方案比选**（2-3家设计单位，5-7天提交）；总图方案稳定后再推进后续深化 | 集团文件§4.3 | 【事实】 |
| **交付标准** | 总图需提供**CAD文件和日照计算结果**；技术指标表需提供**Excel表格，细化至楼栋面积**；户型平面页须附上**该户型的总图位置示意** | 集团文件§4.3 | 【事实】 |

| **成本管控** | "三个极限"：营销判断客户能承受的**售价极限** → 反推项目投入的**成本极限** → 做到**产品力的极限**；直投成本上限 = 货值 × (1 - 税前成本利润率) - 三费 - 地价 | 集团文件§4.5 | 【事实】 |
| **规划效率** | 楼栋**贴线布置**（将间距用足在小区内部）；总图资源配置（利好资源与不利因素量化分析）；设备房、移交配套优先布局于首期建设范围 | 集团文件§4.6 | 【事实】 |
| **设计深度** | 核心筒设计、墙垛预留、外立面（冠顶/门窗/涂料分缝/外轮廓）、室内样板房效果（竞品对标+成本拆解）、社区入口功能及流线、示范区设计（展示策划/后勤办公/接待区）、地库专项（规模控制/单车指标/人防） | 集团文件§4.7 | 【事实】 |

> **【推断】** 从上述诉求可以看出，集团对强排阶段的深度要求非常高，绝非简单的"总图+指标"即可完成。当前项目的实际交付物（总图PPT+Excel指标）与集团要求之间存在显著差距。

#### 2.3.3 指标反复核对反映的流程问题

| 现象 | 问题本质 | 判断来源 |
|--------|---------|---------|
| "这个指标不对"（甲方发现） | 设计方输出的指标数据与甲方预期不符，或甲方内部有其他口径的核算结果 | 【事实】素材汇编§3.2 |
| "贴错了，我更新下"（设计方承认） | 设计方内部**图纸与指标表之间缺乏自动关联**，指标数据是人工从CAD图纸中量取后复制粘贴到Excel，过程容易出错 | 【推断】素材汇编§3.2、§7.2 |
| "14171.26 这个数怎么来的"（甲方追问来源） | 甲方需要**数据的可追溯性**——每个数字必须能说明其计算来源和依据。设计方未能提供清晰的计算过程，导致甲方需要逐个数追问 | 【事实】素材汇编§3.2 |
| 顾瑜答"这个轮廓"（解释面积来源） | 面积数据来自"轮廓"的粗略计算，**未经过正式的面积核算流程**（如按建筑面积计算规范逐条核算） | 【推断】素材汇编§3.2 |

> **【行业经验】** 在规范的强排流程中，指标核算应由专门的经济测算人员或指标核算人员负责，使用标准模板（如《技术经济指标计算表》），按照《建筑工程建筑面积计算规范》GB/T50353逐条计算，并经过复核人审核。当前项目中，指标核算似乎由总图设计师（顾瑜）兼任，在紧张的时间压力下容易出错。
> 
> **【行业经验】** 更根本的问题是：CAD图纸与Excel指标表之间没有建立自动同步机制。如果设计方使用BIM或参数化工具（如NOAH、SketchUp+Excel联动），图纸修改后指标表可以自动更新，避免"贴错了"的问题。

#### 2.3.4 版本管理混乱的问题

| 现象 | 问题描述 | 判断来源 |
|--------|---------|---------|
| PPT文件大小：41.1M → 69.5M → 70.7M | 同一日内文件大小膨胀近一倍，说明**PPT中嵌入了大量图片或模型**，且每次更新都重新嵌入 | 【事实】素材汇编§3.2 |
| 文件名：0626振三街北地块总图(2).pptx、0625振三界北地块项目_t8.dwg | 日期命名不统一（0625/0626），项目名称不统一（"振三街北""振三界北"），版本号不清晰（"(2)""_t8"） | 【事实】素材汇编§10.2 |
| 无版本说明 | 每次发送的PPT中未附带版本说明（如修改了什么、基于哪个版本），接收方无法判断自己手上的是否是最新版 | 【推断】素材汇编§3.2 |
| DWG、PPT、PDF、Excel各自独立更新 | 不同格式文件（DWG总图、PPT汇报、PDF文本、Excel指标）**没有统一的版本同步**，可能出现CAD是最新版但PPT是旧版的情况 | 【推断】素材汇编§7.2 |

> **【行业经验】** 版本管理混乱是设计项目中返工的主要诱因之一。标准做法包括：① 使用版本命名规则（如v1.0_YYYYMMDD_修改内容）；② 每次发送文件附带《版本更新说明》；③ 建立一个共享的网盘/协作平台（如钉钉、企业微信、蓝湖），确保所有参与者看到的是同一版本；④ 设置文件锁定机制，避免多人同时修改同一文件。

**反复的模式观察**：

1. **甲方直接修改设计参数**：【事实】逗逗点豆豆（甲方项目负责人）不是以"建议"的方式，而是直接下达指令"洋房107改成125""把总图和指标改了"。这种指令式调整跳过了设计方的中间分析环节，直接触发了后续多轮技术调整。

2. **"户型线不用新增"的观察**：【事实】在107→125的调整中，甲方特别说明"户型线不用新增"，这意味着户型的外轮廓（交通核、墙体定位）保持不变，只是内部面积分配变化。但一旦面宽从11.8米扩大到12.5米，这个前提就不成立了，总图必须重新排布。

3. **日照作为硬约束的反复**：【事实】14:00甲方明确提到"这几个都是日照问题，所以做架空和配套吗"，说明日照分析结果直接触发了总图调整（架空层面积500㎡在Excel中单独列出，可能与日照规避有关）。

【推断】上述反复的模式揭示了一个关键问题：在强排阶段，总图与户型之间的适配不是"一次性完成"的，而是在多轮迭代中逐步收敛的。每一次户型参数的变化（面积、面宽、层数）都会触发总图的重新排布，而总图排布的结果（日照、间距、消防）又会反过来约束户型的可行性。这种迭代在标准流程中是被允许的，但本项目的问题在于迭代频率过高（一天内3次以上户型调整），且每次调整都由甲方直接下达指令而非经过设计方的专业分析。

### 4.2 立面在强排阶段的定位与缺失

#### 4.2.1 直接观察：立面内容在强排阶段完全缺失

【事实】从项目素材中可以明确观察到：

- 12页PPT中**没有任何一页涉及立面内容**（封面、规划条件、4个总图方案、方案对比、5个户型页）。
- 8MB方案文本PDF中，从素材汇编的摘录来看，内容集中于"总图+户型数据+指标对比"，**未提及立面**。
- 微信沟通中，6月26日全天讨论集中在总图、户型、指标、日照、装配式、人防，**没有任何关于立面的讨论**。

【行业经验】这与行业标准完全一致。根据行业研究素材，"强排与建筑设计无关，主要是在容积率、退线、建筑密度、限高、日照间距等规划指标下，去结合当地不同产品的营销情况，来排出各种追逐利润最大化的极端产品规划方案"（搜狐《周二风暴营销说》2017）。强排阶段的核心是总图和指标，立面不是重点。

#### 4.2.2 从Excel建造标准中提取的立面相关信息

虽然强排阶段未展开立面设计，但Excel建造标准（第二页）中已包含了部分对立面有约束性的条目：

### 5.4 ROM-AI可以介入的环节与操作模式

#### 5.4.1 ROM-AI介入的前提条件分析

| 前提条件 | 当前状态 | ROM-AI介入的可行性 |
|---------|---------|-------------------|
| 项目资料数字化 | 已有CAD、Excel、PPT、PDF、微信截图等数字化文件 | ✅ 可行——ROM-AI可以读取和分析这些文件 |
| 数据结构化程度 | 数据分散在多个文件中，格式不统一，存在矛盾 | ⚠️ 需先标准化——ROM-AI需要统一的数据接口 |
| 决策流程标准化 | 决策靠微信碎片化沟通，无正式任务书、无会议纪要 | ⚠️ 需先建立流程——ROM-AI无法替代非结构化的口头决策 |
| 集团要求明确化 | 集团文件（事业一部PDF）已明确上报要求 | ✅ 可行——ROM-AI可以对照集团要求进行合规检查 |
| 设计团队接受度 | 设计方（霍普）和甲方（事业一部）对AI工具的接受度未知 | ❓ 需验证——取决于组织文化和培训 |

【推断】综合素材汇编§3.2、§7.2、§8.2；`研究发现-展开逻辑与PPT系统.md`§3.1。

#### 5.4.4 ROM-AI介入的边界与限制

| 领域 | ROM-AI无法替代的原因 | 仍需人工完成的环节 |
|------|---------------------|-------------------|
| 设计创意与审美判断 | 总图排布的空间感、立面设计的美学判断、效果图的艺术表达需要人类设计师的专业直觉 | 总图方案创作、立面设计、效果图制作 |
| 甲方决策与谈判 | 方案选择、户型配比、成本取舍涉及甲方的战略判断和利益博弈，需要人际沟通和谈判 | 方案决策、合同谈判、变更审批 |
| 现场踏勘与实地感知 | 地块的实地感受（风向、采光、噪音、周边氛围）无法通过数字化完全传递 | 现场踏勘、实地调研 |
| 跨专业协调 | 结构、设备、景观、精装等专业的技术协调需要多专业人员的面对面沟通 | 专业协调会、技术交底 |
| 规划部门沟通 | 与规划局的沟通涉及政策解读、人际关系、灵活应变，需要人类经验 | 规划沟通、报规流程 |
| 集团评审答辩 | 投决会的现场答辩需要应对评审人员的即时质疑，需要人类的应变能力和专业深度 | 汇报答辩、答疑 |

【行业经验】基于建筑设计行业通用认知。

#### 5.4.7 ROM-AI介入的价值量化（基于本项目素材的推断）

| 问题 | 当前耗时（估算） | ROM-AI介入后的优化 | 节省估算 |
|------|-----------------|-------------------|---------|
| 指标反复核对（"贴错了""这个数怎么来的"） | 每次核对30分钟-1小时，本项目至少3次 | 自动核算+实时同步，消除人工错误 | 节省2-3小时 |
| 日照问题导致总图返工 | 返工一次需2-4小时（重新排布+重新算指标） | 日照前置分析，避免排布后返工 | 节省2-4小时 |
| 户型调整导致总图返工（107→125→126） | 每次调整需1-2小时（重新排布+重新算指标） | 户型库快速替换，自动更新总图和指标 | 节省3-6小时 |
| 版本管理混乱（查找正确版本） | 每次查找10-20分钟，本项目至少5次 | 版本自动命名+历史追溯 | 节省1-2小时 |
| PPT制作（纯文字对比页、指标页手工填充） | 制作12页PPT约4-6小时 | 模板化自动生成，数据自动填充 | 节省2-3小时 |
| 集团合规检查（对照文件逐项核对） | 人工核对约1-2小时 | 规则引擎自动检查，秒级出结果 | 节省1-2小时 |
| 会议纪要整理 | 人工整理约30-60分钟 | 录音转写+自动提取决议 | 节省30-60分钟 |

【推断】基于素材汇编§3.2、§7.1、§7.2；`研究发现-设计成果与人员分工.md`§4.1、§4.2。

**总估算**：在6月26日约10.5小时的密集迭代中，ROM-AI介入可能节省约**12-20小时**的重复性工作时间，将核心设计时间从"反复核对和返工"转移到"方案优化和创意决策"上。【推断】

#### 5.4.8 ROM-AI操作模式的实施前提

| 前提条件 | 当前状态 | 需要建立的机制 |
|---------|---------|---------------|
| 数据接口标准化 | CAD、Excel、PPT格式不统一，数据提取困难 | 建立统一的数据交换格式（如JSON/XML）或API接口 |
| 集团模板数字化 | 集团PPT模板未数字化，结构不固定 | 将集团文件中的上报要求转化为结构化模板 |
| 户型库参数化 | 户型数据分散在PDF和CAD中，未参数化 | 建立参数化户型库（面积、面宽、进深、交通核等） |
| 计算规则书面化 | 装配式、人防等计算规则靠微信口头确认 | 将计算规则书面化并嵌入ROM-AI的规则引擎 |
| 权限与数据安全 | 项目资料涉及甲方商业机密 | 建立数据分级权限、加密传输、本地部署等安全机制 |
| 设计团队培训 | 设计方和甲方对AI工具的接受度未知 | 提供培训、建立反馈机制、逐步推广 |

【推断】基于素材汇编§3.2、§7.2；`研究发现-展开逻辑与PPT系统.md`§3.1、§3.3。
