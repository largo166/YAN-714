### 1.3 缺失资料的后果分析

| 缺失资料 | 缺失后果 | 判断来源 |
|----------|---------|---------|
| **市场调研/竞品分析** | 户型配比（107/129/125/126/108/155）的决策缺乏市场数据支撑，极有可能与目标客群需求错位。行业经验表明，"营销部的户型配比可能朝令夕改，导致设计院反复调整"——本项目6月26日一天内户型调整4次（107→125→126，新增108、155），正是这一模式的典型表现。 | 【事实】素材汇编§3.2、§7.1；行业标准§2.3 |
| **设计任务书** | 设计方接收的需求来自微信碎片化指令，而非系统化的书面任务书。这导致：① 设计方无法一次性准确理解甲方全部需求；② 需求变更无书面记录，版本追溯困难；③ 设计方被动响应而非主动预判。6月26日一天内的密集迭代（4版总图+多次户型调整）与此直接相关。 | 【事实】素材汇编§7.2；行业标准§2.3 |
| **成本指标/建安成本标准** | 王志鹏反复追问"单车指标多少""装配式和人工都是按照地上面积+抬板车库面积？"——说明成本核算规则尚未明确。缺失成本上限会导致：① 设计方无法按成本极限进行"限额设计"；② 方案报集团时可能因成本超标被否；③ 集团文件明确要求"成本适配三个极限"（售价极限→成本极限→产品力极限），缺少成本指标则无法完成此闭环。 | 【事实】素材汇编§3.2、§4.5；王志鹏微信追问 |
| **地质勘察报告** | 地库设计（面积10,764㎡、人防2,986㎡）可能脱离实际地质条件。石家庄地区"筏板+CFG"（北地块）和"筏板+灌注桩"（西北片区）的基础形式差异即与地质有关。若地下水位不明或土质条件不利，地库方案后期可能大规模变更。 | 【事实】素材汇编§1.1建造标准；行业标准§1.5 |
| **城市技术管理规定（石家庄本地）** | 已有数据（装配式40%、被动房10%、车位配比等）来源不明。若设计方未系统研读石家庄本地技术规定，可能遗漏地方特殊要求（如停车位配建标准、绿色建筑要求、海绵城市要求），导致报规不通过。 | 【事实】素材汇编§1.1；行业标准§2.4 |
| **日照分析报告（独立报告）** | 逗逗点豆豆明确说"这几个都是日照问题，所以做架空和配套吗"——日照是核心约束。但PPT中仅提及"客体排除法""界外影响需降层"，未见正式日照分析报告。行业标准指出："界外日照分析"最容易被跳过，后果是"排布完成后发现对周边建筑日照超限，被迫调整总图"——本项目已出现此迹象（"界外影响需降层"）。 | 【事实】素材汇编§3.2、§6；行业标准§2.4 |
| **经济测算表** | 集团文件明确要求"必须包含"，且"未包含以上专项，不允许上会审议"。当前缺失意味着项目无法进入集团评审流程。经济测算的缺失也使得设计方无法从"货值最大化"角度优化产品配比，只能机械响应甲方的户型调整指令。 | 【事实】集团文件§4.1；行业标准§6.4 |
| **一房一价专项** | 集团文件"未包含以上专项，不允许上会审议"。该专项是营销判断客户能承受售价极限的核心依据，缺失则无法确定产品定价策略，进而无法反推成本极限。 | 【事实】集团文件§4.1 |
| **成本适配专项** | 集团文件"未包含以上专项，不允许上会审议"。该专项要求将成本分解为"示范区总成本、刚性成本、功能性成本、弹性成本"四象限，并做到"三个极限"。缺失意味着成本管控无据可依。 | 【事实】集团文件§4.1、§4.5 |
| **地库专项方案** | 集团文件"未包含以上专项，不允许上会审议"。王志鹏已关注"单车指标"（36㎡/车位），但地库专项方案（规模控制、人防设计、单车指标优化）尚未形成。地库是建安成本的大头（通常占总投资15-25%），专项缺失导致成本失控风险。 | 【事实】集团文件§4.1、§4.7；王志鹏微信追问 |
| **首层拼合总平面** | 集团文件"未包含以上专项，不允许上会审议"。该图纸是报规的关键文件，缺失意味着当前方案深度不足以支撑上报。 | 【事实】集团文件§4.1 |
| **会议纪要** | 腾讯会议已召开（6月26日19:16），但无书面纪要。口头沟通内容（如方案选定、户型调整决议、指标核对结论）没有书面记录，后续争议无法追溯。微信碎片化信息容易被新消息淹没，且无法作为正式决策依据。 | 【事实】素材汇编§3.2、§7.2；行业标准§2.3 |

| **无法追溯** | 微信消息被新消息淹没，手绘草图没有编号和归档，后续需要确认"当时说的是哪个版本"时难以查找 | 【事实】素材汇编§3.2 |
| **缺少技术审核** | 甲方手绘的户型草图可能不符合结构规范（如承重墙位置、开间模数），设计方若直接按图绘制，后期结构审图可能发现问题 | 【推断】素材汇编§3.2；行业标准§3.2.5 |
| **口头指令≠书面变更** | 甲方的"洋房107改成125"是微信口头指令，而非正式的《设计变更通知单》。如果后期产生争议，没有书面记录证明变更的发起方和批准流程 | 【事实】素材汇编§3.2；行业标准§2.3 |
| **多方信息冲突** | 逗逗点豆豆（设计部）和王志鹏（成本/技术）同时发指令，如果两人的指令存在冲突（如面宽要求不同），设计方无法判断听谁的 | 【推断】素材汇编§3.1、§3.2 |

#### 3.5.2 优化空间

| 优化方向 | 说明 | 判断来源 |
|----------|------|---------|
| **建立《设计任务书》** | 项目启动时，甲方应提供书面《设计任务书》，包含：规划条件、产品定位、户型配比、交付标准、特殊要求、时间节点。这是设计方工作的基础依据。 | 【行业经验】行业标准§1.3 |
| **建立《设计变更通知单》机制** | 任何需求变更（如户型调整、面积修改）应通过书面《设计变更通知单》发起，注明变更原因、变更内容、对工期和费用的影响、甲方签字确认。 | 【行业经验】 |
| **甲方提供CAD底图或标准户型库** | 若甲方有具体的空间构想，应提供CAD格式的草图或标准户型模块，而非手绘草图。这样可以确保精度，减少设计方的理解偏差。 | 【行业经验】 |
| **建立微信群信息归档机制** | 即使使用微信沟通，也应指定专人（如甲方设计部助理或设计方项目秘书）定期整理沟通记录，形成《项目沟通纪要》，每周发送给所有参与方确认。 | 【行业经验】 |

### 3.6 腾讯会议无纪要、口头沟通靠微信确认的信息传递风险

| 风险项 | 具体表现 | 判断来源 |

| **会议决议无书面记录** | 6月26日17:18-18:18召开腾讯会议，但会后未形成会议纪要。会议中达成的决议（如方案选择、户型调整、指标确认）仅通过后续微信碎片化信息传递 | 【事实】素材汇编§3.2（19:16发会议邀请，说明17:18-18:18已开完） |

> **【行业经验】** 标准做法：每次会议后24小时内由设计方或甲方指定人员形成《会议纪要》，包含：会议时间、参会人员、讨论事项、决议事项、待办事项（责任人+完成时间）、下次会议时间。纪要发送给所有参会方确认，如有异议在24小时内提出。这样可以确保信息传递的准确性和可追溯性。
> 
> **【行业经验】** 对于本项目，6月26日的会议后应形成纪要，明确：① 最终选定的方案（方案1不抬板）；② 锁定的户型配比（中高层108/129、洋房126、南地块155）；③ 确认的指标数据（以Excel为准）；④ 下一步工作计划（如补充日照分析、经济测算等）。如果这些决议未能书面锁定，后续很可能再次调整。
