# ROM-AI "差异化锻造链"设计分析

> **前提**：只分析，不改代码。基于 Claude Desktop 提供的 sharpness 版设计稿，从**技术可行性**、**产品定位**、**与现有 ROM-AI 的兼容性**三个维度给出判断。

---

## 一、核心判断：这是 ROM-AI 从"工具"到"思维伙伴"的跃迁

### 1.1 定义的转变

| 维度 | 原来的 ROM-AI | sharpness 版 ROM-AI |
|------|-------------|-------------------|
| 定位 | AI 效率工具（帮设计师省时间） | AI 概念副驾（逼设计师想出别人想不到的） |
| 核心指标 | 22 个技能覆盖多少场景 | 4 个技能链能逼出多少"非共识 main idea" |
| 卖点 | 会议纪要/PPT/生图/竞品分析 | 先杀平庸 → 再逼出那一条砸中评委的 |
| 用户价值 | 少做重复劳动 | 少做安全平庸，多做锋利差异 |

**这个转变是质的飞跃。** 从"帮你更快"到"帮你更不一样"——这直接切中了设计公司最底层的焦虑：不是"做不完"，而是"做不赢"。

### 1.2 为什么原来的定义不够

原来的 ROM-AI 逻辑：22 个技能 → 覆盖设计工作全流程 → 效率提升 → 设计师更轻松。

但这个逻辑有个漏洞：**大模型天然回归均值**。你喂它越多"规划条件/甲方诉求/公司记忆"，它越给你"四平八稳、同行也会给"的概念壳。这意味着——

> **记忆层只保证"不离谱、可辩护"，不保证"砸中评委"。**

25条妙记中反复提到的痛点不是"没时间做方案"，而是"概念不够锋利""和同行撞车""评委见过太多类似的"。所以 sharpness 版的设计直接回应了真问题。

## 二、四个技能逐一分析

### 2.1 concept（概念逼问器）——最核心的重新定义

**原来的 concept**：发散 N 个概念方向 → 设计师挑一个深化。
- 问题：产出"绿色生态/在地文化/共享客厅"这类放之四海皆准的壳。
- 原因：大模型从关键词联想，不从项目矛盾长。

**新的 concept**：列红海 → 锁张力 → 逼非共识。
- **列红海**："这类项目+这个甲方，90% 的投标会提哪 5 个概念？"→ 明确标"会撞车，不许用"。
- **锁张力**："本项目里，哪条硬约束 vs 甲方诉求/场地是冲突的？哪个机会是同行普遍忽略的？"
- **逼非共识**："针对每个张力，给 1 条非共识概念逻辑——一句 main idea + 解了哪个张力 + 为什么评委没见过 + 最大风险。"

**技术可行性**：✅ 高
- 这三步都是 prompt 工程，不需要新模型或新数据。
- "列红海"依赖大模型的通识（它知道住宅投标通常提什么概念），不需要知识库。
- "锁张力"依赖项目条件（规划条件/甲方诉求/场地），这些 ROM-AI 已有（A1-A8 认知模块）。

**潜在风险**：
- 如果项目类型非常细分（如"宋式展示区"），大模型可能不知道"红海"——因为训练数据里这类案例少。这时候"列红海"会不准确。
- 如果项目条件非常普通（标准地块、常规甲方），可能没有明显"张力"——concept 的第二步会卡住。

**建议**：先验证 P1（盲评），用 3-5 个真实投标测试"列红海→锁张力→逼非共识"的产出是否比裸 ChatGPT 更锋利。

### 2.2 compete（竞品研判）——方向完全反转

**原来的 compete**：总结同类项目怎么做 → 帮你更像同行。
- 问题：方向反了。"帮你更像同行"=抹平差异=反 sharpness。

**新的 compete**：红海测绘 + 蓝海猎手。
- **红海测绘**："同类投标普遍打哪几张牌？哪些已烂大街？"
- **疲劳点/盲区**："评委这两年看腻了什么？同行集体忽略了本项目的哪个机会？"
- **反共识钩子**："要差异化，可以反哪条共识？给 2 个'别人不敢/没想到'的切入，各标风险。"

**关键设计**：compete 的产出**必须喂给 concept 当张力弹药**。
- 红海 = 要避（告诉 concept 这些概念不许用）
- 盲区 = 可切（告诉 concept 这个方向是无人区）
- 否则 compete 是独立废话。

**技术可行性**：✅ 高
- 三步都是 prompt 工程。
- "红海测绘"依赖大模型的通识（它知道住宅投标通常有哪些手法）。
- "疲劳点/盲区"需要大模型有"行业趋势"的判断——这更偏推理，但 deepseek-reasoner 可以胜任。

**潜在风险**：
- 如果没有真实竞品数据（如"这个地块周边的投标方案"），compete 只能基于通识推测。通识推测的"盲区"可能不准确。
- 需要明确标注"基于通识推测，非实证"——不靠编造撑 sharpness。

### 2.3 writer（main idea 提炼器）——从"扩写"翻转为"检验"

**原来的 writer**：把概念扩写成投标文本/提纲。纯表达层，无概念增量。
- 问题：定位错了。writer 是下游"表达"，不产 idea。

**新的 writer**：main idea 提炼器 + 概念锋利度检验器。
- **逼一句话**："把这个概念压成评委 10 秒记得住、且换成别的项目就不成立的一句 main idea。"
- **三段钩子**：痛点（甲方/场地的真问题）→ 反转（非共识解）→ 证据（怎么落）。
- **自检打回**："这句话套到竞品项目还成立吗？成立 = 太泛，打回 concept 重想。"

**这是天才的设定**。
- writer 不产 idea，它**验证 idea 是否够锋利**。
- "换项目测试"是最廉价的客观闸门：一句话套别的项目还成立 = 概念没到位。
- writer 成为 concept 的"质量阀"——写不出独占性的一句话，就证明概念没到位。

**技术可行性**：✅ 高
- 三步都是 prompt 工程。
- "换项目测试"需要大模型判断"这句话是否泛化"——这本身就是推理能力，deepseek-reasoner 可以胜任。

### 2.4 judge（平庸刺客）——从"评审打分"到"杀平庸留锋利"

**原来的 judge**：方案评审（单模型点评）。
- 问题：审计发现 judge 串台跑了 task！点"方案评审"实际跑的是"任务安排"prompt。
- 更严重的问题：单模型点评会附和、会泛（"很好，建议加强 X"）。真正该干的是"杀平庸"，不是"打分通过"。

**新的 judge**：平庸刺客 / 差异化守门人。
- **撞车检测**："哪几个概念评委今年已见过 ≥3 次？标'红海，杀'。"
- **三视角各捅一刀**（甲方代言/规范现实/总监品质），每视角**必须引项目真实条件反驳，不许说好话**。
- **留一补刀**："唯一值得往下走的是哪个？致命短板是什么？补哪一刀能让它砸中评委？"

**与现有 MoA 设计委员会的关系**：
- 现有设计委员会：输出评图报告（检查清单、亮点、问题、next_steps）——偏"诊断"。
- 新的 judge：输出"杀 N 留 1 + 补刀方向"——偏"裁决"。
- 两者可以**共用引擎**（都是 MoA 对抗逻辑），但产物不同。
- 建议：保留现有设计委员会（用于正式评审报告），新增 judge（用于概念筛选阶段）。

**技术可行性**：✅ 高
- 三视角对抗可以用 MoA 实现（已有技术）。
- "必须引项目真实条件反驳"需要注入 A1-A8 认知数据（ROM-AI 已有）。
- "不许说好话"需要 prompt 非常激进——这需要调试，但技术上是可行的。

**潜在风险**：
- 大模型天然倾向"温和"——如果 prompt 不够激进，judge 可能不敢杀。
- 需要验收指标："每轮至少毙过半，都说不错 = 没用。"

## 三、"差异化锻造链"的设计精妙之处

```
compete(测红海·找盲区) → concept(从张力逼非共识) → judge(杀平庸·留1·补刀) → writer(逼独占性一句话·写不出就打回 concept)
```

### 3.1 链的逻辑：每一步都是"消除平庸"

| 步骤 | 职责 | 消除什么平庸 |
|------|------|------------|
| compete | 给弹药 | 消除"不知道同行会做什么"的盲目 |
| concept | 逼角度 | 消除"从关键词联想、不从矛盾长"的概念壳 |
| judge | 杀平庸 | 消除"撞车不自知""自嗨"的伪差异化 |
| writer | 验独占 | 消除"万能宣传语"式的模糊概念 |

**这不是四个并列的问答按钮，这是一条生产线。** 每一步的产物都是下一步的输入，每一步的职责都是"消除平庸"。

### 3.2 与现有 ROM-AI 的关系

**不冲突，是叠加**。

- 现有 22 技能 = **工具箱**（日常设计工作：纪要/PPT/生图/任务）
- 新 4 技能链 = **核心引擎**（投标关键期：逼出差异化 main idea）

设计师的日常：用 22 技能做各种事。
设计师投标前：用 4 技能链跑一轮"差异化锻造"。

两者可以**完美共存**——22 技能是"效率层"，4 技能链是"竞争力层"。

### 3.3 实现路径

**不需要改架构**，只需要改 prompt。

| 改动 | 范围 | 工作量 |
|------|------|--------|
| concept 的 prompt 重写 | `_SKILL_PROMPTS["concept"]` | 1 条 prompt（约 500 字） |
| compete 的 prompt 重写 | `_SKILL_PROMPTS["compete"]` | 1 条 prompt（约 500 字） |
| writer 的 prompt 重写 | `_SKILL_PROMPTS["writer"]` | 1 条 prompt（约 500 字） |
| judge 的 prompt 重写 | 新增 `_SKILL_PROMPTS["judge"]` | 1 条 prompt（约 500 字） |
| 修复 judge 串台 | `skills.py` 的 RUN_AS 映射 | 1 行代码 |
| 链的 UI 提示 | 前端增加"建议下一步"按钮 | 前端组件调整 |

**总计：4 条 prompt + 1 行修复 + 前端微调。工作量极小，但价值极大。**

## 四、可行性评估

### 4.1 能实现的（✅）

- **概念逼问**：通过 prompt 工程让大模型"列红海→锁张力→逼非共识"——可行。
- **竞品盲区**：通过 prompt 让大模型"总结同行→找盲区→给反共识钩子"——可行。
- **写一句话**：通过 prompt 让大模型"压成一句话→换项目测试"——可行。
- **杀平庸**：通过 MoA 对抗（多角色互怼）——已有技术。
- **链的 UI**：前端在技能结果卡上增加"建议下一步"按钮，引导用户按链执行——可行。

### 4.2 有难度的（⚠️）

- **"红海"需要真实知识**：如果项目类型非常细分（如"宋式展示区"），大模型可能不知道"红海"。这需要知识库沉淀"历年投标概念"。
- **"张力"可能不存在**：如果项目条件非常普通（标准地块、常规甲方），可能没有明显"矛盾"。这时候 concept 的第二步会卡住，需要 fallback 到"从场地微特征找差异化"。
- **judge 的敢杀率**：大模型天然倾向"温和"，可能不敢杀。需要 prompt 非常激进，且需要验收"每轮至少毙过半"。
- **换项目测试的可靠性**：writer 的"自检打回"需要大模型能判断"这句话是否泛化"——这本身就是高难度推理，可能误判。

### 4.3 暂时接不了的（❌）

- **真正的创造性跳跃**：工具给牌面、给张力、给反例，**那一跳是主创的**。声称 AI 代想原创 = 伪需求。
- **审美/空间品质高低判断**：这是设计师的直觉，AI 无法替代。

## 五、与现有审计报告的对比

| 审计报告的问题 | sharpness 版是否解决 |
|-------------|-------------------|
| 批量接入未接（资料整理效率） | ❌ 不解决——这是工具层问题，不是 sharpness 层 |
| 纪要回流未接（知识沉淀） | ⚠️ 部分解决——compete 的"红海"需要知识库沉淀历年概念 |
| 主动派活未接（任务管理） | ❌ 不解决——这是工具层问题 |
| risks 恒空（风险看板） | ❌ 不解决——这是工具层问题 |
| 22 技能是通用问答（无差异化） | ✅ **核心解决**——这是 sharpness 版的全部重点 |

**结论**：sharpness 版不解决"工具层"问题（批量接入/任务管理/风险看板），但它解决了一个更底层的问题——**ROM-AI 到底帮设计师什么？** 不是"更快"，而是"更不一样"。

## 六、最终建议

### 6.1 立即验证（P1）

**拿 3-5 个真实投标，做盲评**：
- A 组：设计师裸 ChatGPT 30 分钟
- B 组：compete→concept→judge→writer 链
- 盲评三项：**砸中概率 / 差异化度 / 独占性（换项目是否还成立）**

**如果链赢不了裸 ChatGPT 在"砸中+独占"上，这个产品定位就不成立**——这是最该先证的事。

### 6.2 如果验证通过

1. **重写 4 个技能的 prompt**（按 sharpness 版设计稿）。
2. **修复 judge 串台**（RUN_AS 映射）。
3. **前端增加"建议下一步"按钮**（引导用户按链执行）。
4. **保留现有 22 技能**（作为工具箱），但把"差异化锻造链"作为核心卖点。
5. **知识库补充"历年投标概念"**（让 compete 的"红海测绘"有真实数据）。

### 6.3 价值主张（对外）

> **"ROM-AI 不替你想方案，它逼你想出别人想不到的那一条——摊开评委见腻的红海，从项目矛盾里逼出你的非共识 main idea。"**

短 slogan：**"先杀平庸，再逼出那一条砸中评委的。"**

---

## 七、总结

**这份 sharpness 版设计稿是 ROM-AI 从"工具"到"思维伙伴"的跃迁设计。**

它抓住了设计公司最核心的痛点：不是"做不完"，而是"做不赢"。它重新定义了四个技能的角色，从"功能"变成了"思维武器"。它提出了"差异化锻造链"——这是 ROM-AI 真正的产品差异化。

**技术实现成本极低**（4 条 prompt + 1 行修复），但**产品定位价值极高**（从"效率工具"升级为"概念副驾"）。

**最该警惕的**：别对外吹错。如果验证发现"链赢不了裸 ChatGPT"，那就老老实实说"ROM-AI 是效率工具"，不要包装成"差异化引擎"。

**最该兴奋的**：如果验证通过，ROM-AI 就不仅是"建筑设计的 AI 工具"，而是**"建筑设计的 AI 概念副驾"**——这个定位，市面上没有竞品。
