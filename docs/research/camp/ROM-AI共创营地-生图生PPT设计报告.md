# ROM-AI 共创营地：生图 + 生 PPT 综合产品设计报告

> **报告日期**：2026-07-10
> **研究对象**：EasyMap Layout、Gamma、Beautiful.ai、Canva、Pitch、Krea、PromeAI、Vizcom、Midjourney、Adobe Firefly
> **目标**：为 ROM-AI"共创营地"模块设计"生图 + 生 PPT"的产品路径
> **核心原则**：半自动比全自动更可靠，建筑师主导判断，本地优先

---

## 一、ROM-AI 现有代码底座评估

基于对 `exporters.py`、`image_assets.py` 及用户描述的代码现状分析，ROM-AI 的"生图+生 PPT"能力底座已有以下基础：

### 1.1 已具备的底层能力

| 能力 | 文件 | 状态 | 说明 |
|------|------|------|------|
| **PPTX 导出** | `exporters.py` | ✅ 后端可用 | `build_pptx(data, slide_images)` 已支持：封面页 + 内容页（标题+核心观点+要点），右侧有图片资产插槽（第 93-106 行），`visualSuggestion` 降级为图下注脚或占位框 |
| **图片资产提取** | `image_assets.py` | ✅ 后端可用 | `extract_pptx/docx/pdf()` 从三种文件类型提取嵌入图片，带 `slide_no/page_no`、尺寸、图注。`classify_by_name()` 已按强关键词自动分类（总图/模型/材质/效果图/参考图等） |
| **技能结果沉淀** | `skills.py` | ✅ 后端可用 | 技能系统可生成 `ppt` 类型结果，含 `slides` 数组（title/keyMessage/bullets/visualSuggestion/speakerNotes/sourceRefs） |
| **错误状态暴露** | `useProjectLive.ts` 等 | ✅ 前端可用 | 数据层带 `err`，前端能显示"部分数据加载失败" |
| **事件广播** | `projectBridge.ts` | ✅ 已修复 | 项目创建/更新后广播刷新，协作板自动更新 |
| **入库反馈** | `CleanupWizard.tsx` | ✅ 已修复 | 显示入库文档数、分片数、截断页码、图片资产提取数量 |

### 1.2 前端尚未呈现的"隐藏能力"

| 能力 | 后端状态 | 前端状态 | 缺失环节 |
|------|---------|---------|---------|
| PPTX 导出 | ✅ 完整 | ❌ 无正式入口 | 需要"PPT 图文大纲编辑器"页面 |
| 图片资产池 | ✅ 提取+分类 | ❌ 无画廊界面 | 需要"项目图片库"筛选/浏览/选图界面 |
| 图片槽位匹配 | ✅ 数据结构有 | ❌ 无交互层 | 需要"槽位推荐+用户确认"的中间层 |
| 跨项目知识沉淀 | ✅ 后端接口 | ❌ 五板无入口 | 需要"历史标杆库/竞品判断库"前端 |
| MoA 多智能体链路 | ✅ 预设存在 | ❌ 离散点状 | 需要"概念→竞品→评审"连续链路前端 |
| 结果发送/汇报分发 | ✅ 后端接口 | ❌ 无流程 | 需要"发送给谁"的清晰 UI 流程 |
| 重解析/重入库 | ✅ 后端接口 | ❌ 无状态面板 | 需要"入库状态看板" |

### 1.3 底座的战略判断

**好消息**：ROM-AI 的后端已经具备"从资料到 PPTX"的完整链路——资料入库→图片提取→分类→技能生成 PPT 大纲→`build_pptx` 渲染。这不是从零开始，而是**前端还差一个"图文大纲工作台"把后端能力串联成产品功能**。

**关键缺口**：`exporters.py` 的 `slide_images` 参数接受的是 `dict[int, str]`（页号→图片路径），但前端没有一个界面让用户"看到每页需要什么图、从项目资料里挑图、一键填入槽位"。这个中间层就是 EasyMap 的"黑色占位区"所代表的价值。

## 二、PPT 产品研究总览

### 2.1 五款产品本质对比

| 产品 | 一句话定位 | 图片范式 | 对 ROM-AI 最大启发 |
|------|-----------|---------|-------------------|
| **EasyMap Layout** | 建筑作品集半自动图板排版器 | **先占位后填图**（黑色占位区+批量填图） | **图片槽位体系 + 三段式工作流** |
| **Gamma** | AI 原生内容生成器（提示词→大纲→Deck） | 生成时自动配图（AI/素材库） | **AI 大纲编排 + 主题一键切换**，但不可学全自动生成 |
| **Beautiful.ai** | Smart Slides 自动排版工具 | 内容驱动排版（图片触发重排） | **自动排版规则 + 品牌主题一致性** |
| **Canva Magic Design** | 全球最大设计平台的 AI 演示扩展 | AI 自动配图 + 100M+ 素材库 | **素材库生态 + Brand Kit**，但不可学通用平台形态 |
| **Pitch** | Figma 式团队协作演示平台 | 模板预设占位 + 素材源集成 | **Slide 状态 + 版本历史 + 协作评论** |

### 2.2 图片处理三种范式对比

| 范式 | 代表 | 特征 | ROM-AI 适用性 |
|------|------|------|--------------|
| **先占位后填图** | EasyMap | 黑色占位区→人工/批量替换 | ✅ **最匹配**——建筑师需要控制每张图的精确位置 |
| **生成时自动配图** | Gamma/Canva/Pitch | AI 自动选图或素材库匹配 | ⚠️ 辅助可用，但不可作为主力——建筑图不能 AI 幻觉 |
| **内容驱动排版** | Beautiful.ai | 添加图片触发整体重排 | ⚠️ 限制太多，建筑师需要精确控制 |

### 2.3 贯穿五家的核心教训

1. **AI 自动配图不适合建筑场景**：Gamma 的"自动配图"是建筑汇报的最大风险——AI 可能生成一张"看起来像那么回事"但实际与项目无关的图，这在建筑投标中是不可接受的。
2. **EasyMap 的"三段式"是最可靠的工作流**：选模板→占位→填图→精调→导出。没有 AI 幻觉风险，设计师全程控制。
3. **Gamma 导出 PPT 格式崩坏是最大投诉**：这说明"网页原生 Deck→PPT 导出"不是 ROM-AI 应该走的路径。ROM-AI 应该以 PPTX 为原生目标格式。

## 三、生图产品研究总览

### 3.1 五款产品本质对比

| 产品 | 核心交互 | 实时探索 | 局部修改 | 建筑适配 | 对 ROM-AI 启发优先级 |
|------|---------|---------|---------|---------|---------------------|
| **Krea** | 左右分栏实时画布（50ms 延迟） | ✅ 实时 | ✅ Inpainting | ⭐⭐⭐⭐ | 🔴 **极高** |
| **PromeAI** | 上传→选风格→生成（十几秒） | ❌ 异步 | ✅ 局部重绘 | ⭐⭐⭐⭐⭐ | 🟡 **高** |
| **Vizcom** | 左绘右渲实时同步 | ✅ 实时 | ✅ 区域编辑 | ⭐⭐⭐ | 🟢 **中** |
| **Midjourney** | Prompt + 参数 | ❌ 异步 | ✅ Vary Region | ⭐⭐⭐ | 🟡 **高**（质量参照） |
| **Adobe Firefly** | 框选+描述填充（Generative Fill） | ❌ 异步 | ✅ **最强** | ⭐⭐⭐⭐ | 🔴 **极高** |

### 3.2 对 ROM-AI 最关键的两项能力

**① Krea 的实时画布**：解决"快速概念草图"的效率问题。用户涂几笔/放参考图，右侧 50ms 内实时渲染。这种"所画即所得"的反馈回路是建筑师"体块推敲→氛围验证"的理想交互。

**② Adobe Firefly 的框选区域生成（Generative Fill）**：解决"PPT 页面缺一张图"的精准补位问题。用户在 PPT 编辑器中框选一个空白区域→输入描述→AI 生成匹配的图片。Firefly 的"自动匹配光影透视"（Harmonize）解决了合成真实感问题。

### 3.3 建筑场景的生图策略

| 场景 | 推荐工具/策略 | 原因 |
|------|-------------|------|
| 快速概念探索（草图→氛围） | Krea 实时画布 | 迭代成本接近零，鼓励探索更多方向 |
| 草图→照片级渲染（方案汇报） | PromeAI Sketch Rendering | 3000+ 建筑模板，透视/光影参数可控 |
| 最终视觉质量参照 | Midjourney | 单张画质天花板，但仅做"头脑风暴"而非"方案交付" |
| PPT 页面缺图补位 | Adobe Firefly Generative Fill | 框选区域精准生成，光影自动匹配 |
| 商用安全（甲方/投标） | Adobe Firefly | 授权训练数据+法律兜底，唯一商用零风险 |

## 四、ROM-AI 共创营地：生图 + 生 PPT 产品路径

### 4.1 产品哲学：不是"AI 自动生成 PPT"，而是"项目资料组织成图文研判底稿"

> **核心主张**：ROM-AI 不替建筑师做判断，而是帮建筑师把项目资料、会议决议、甲方诉求、风险清单，组织成一套"可审查判断、可替换图片、可导出交付"的图文底稿。

这个定位与五家竞品的根本区别：
- **Gamma**：AI 全自动生成→用户微调（建筑师不信任全自动）
- **Beautiful.ai**：内容输入→自动排版（限制太多，建筑师需要精确控制）
- **EasyMap**：模板+填图（无 AI，纯手动——ROM-AI 要加一层"智能推荐"）
- **Canva**：通用设计平台（不是建筑专用）
- **ROM-AI**：**项目资料→结构化大纲→智能推荐图片→人工确认→导出 PPT**（半自动+建筑师主导）

### 4.2 分阶段产品路径

#### Phase 1：PPT 图文大纲 1.0（短期，2-4 周）

**目标**：输入项目资料，输出 12-20 页结构化大纲，带图片槽位建议。

**工作流**：

```
项目资料（已入库的文档/图片/会议纪要）
    ↓
技能系统分析（concept/compete/review 等 MoA 预设）
    ↓
生成结构化大纲 JSON（title/keyMessage/bullets/visualSuggestion/asset_type/slide_no）
    ↓
【前端新界面】PPT 图文大纲编辑器
    ├─ 左侧：大纲导航（12-20 页缩略列表）
    ├─ 中间：当前页详情（标题+核心观点+要点+图片槽位）
    ├─ 右侧：图片槽位（黑色/灰色占位区，带 asset_type 标签）
    │       ├─ "建议图：区位分析图" → 点击 → 从项目图片池推荐 3 张
    │       ├─ "建议图：效果图" → 点击 → 从项目图片池推荐 3 张
    │       └─ "无可用图片" → 保留占位，或 AI 生成补位图
    └─ 底部：批量操作（锁定/解锁/删除/上移/下移）
    ↓
用户审查每页：改文字、换图片、锁定页面、标记"缺图"
    ↓
导出 PPTX（调用已有 build_pptx）
```

**关键数据结构**（基于现有底座扩展）：

```typescript
interface Slide {
  no: number;
  title: string;
  keyMessage: string;
  bullets: string[];
  visualSuggestion: string;      // 已有的建议图描述
  asset_type: "plan" | "render" | "reference" | "model" | "material" | "";  // 新增：图片槽位类型
  imageSlots: ImageSlot[];       // 新增：1-3 个图片槽位
  status: "draft" | "reviewed" | "locked" | "needs_image";  // 新增：页面状态
  speakerNotes?: string;
  sourceRefs?: string[];
}

interface ImageSlot {
  id: string;
  asset_type: string;           // 期望的图片类型（如 "render"）
  suggestedImages: string[];    // 系统推荐 3 张图片路径
  selectedImage: string | null; // 用户选中的图片路径
  position: "left" | "right" | "full" | "top" | "bottom";  // 在页面中的位置
}
```

**后端依赖**：
- `exporters.py` 的 `build_pptx` 已支持 `slide_images` 参数，只需前端传入 `{slide_no: image_path}`
- `image_assets.py` 的 `classify_by_name` 已支持按类型分类，推荐算法可直接复用

**前端新界面**：
- 在"共创营地"或"汇报出口"模块新增一个"PPT 图文大纲"Tab
- 页面布局参考 EasyMap：左侧大纲导航（像 EasyMap 的 starter 选择）+ 中间编辑区 + 右侧图片槽位
- 图片槽位用灰色/黑色占位区，带 `asset_type` 标签（如"🖼 效果图"）

**验收标准**：
- 从项目资料生成大纲：端到端 30 秒内完成（不含 LLM 生成时间）
- 图片推荐准确率：按 `asset_type` 推荐的图片，用户采纳率 ≥ 60%
- 导出 PPTX：每页正确渲染标题、要点、图片，格式不崩

#### Phase 2：项目图片池（短期，与 Phase 1 并行）

**目标**：把用户上传的 PPT、PDF、Word、图片包里的图统一抽出，自动标记，可筛选浏览。

**工作流**：

```
文件上传（PPT/PDF/Word/图片包）
    ↓
后端 extract + classify（已有 image_assets.py）
    ↓
【前端新界面】项目图片池画廊
    ├─ 顶部筛选：全部 / 总图 / 效果图 / 竞品图 / 材质图 / 现场图 / 营销图 / 参考图
    ├─ 网格视图：缩略图 + 尺寸 + 来源页 + 分类标签
    ├─ 点击展开：大图 + 来源信息（哪个文件/第几页/提取时间）+ 手动改分类
    └─ 搜索：按文件名/图注/来源关键词搜索
    ↓
PPT 大纲编辑器中点击槽位 → 打开图片池浮层 → 筛选 → 选择 → 填入槽位
```

**前端新界面**：
- 在"数据基地"模块新增"图片资产"Tab，或在 PPT 编辑器中内嵌图片池浮层
- 图片池需要支持：拖拽排序、批量选择、手动分类、删除

**验收标准**：
- 一个 50 页 PPT 的图片提取时间 ≤ 5 秒
- 自动分类准确率：在已定义的关键词范围内，分类正确率 ≥ 70%（用户可手动修正）
- 图片池支持 1000+ 张图片的流畅浏览和筛选

#### Phase 3：图片槽位 + 批量填图（中期，4-8 周）

**目标**：每页 PPT 有 1-3 个图片槽，系统推荐图片，用户一键替换或批量填图。

**核心机制**（EasyMap 启发）：

```
【批量填图】（BATCH FILL 的 ROM-AI 版）
1. 系统扫描所有"未填槽位"
2. 对每个槽位：按 asset_type 从图片池匹配最高相关度的 3 张
3. 展示"批量填图预览"：每个槽位显示推荐图，用户可逐张确认或全部接受
4. 用户确认后，批量填入
5. 单点精调：点击任意槽位 → 图片池浮层 → 替换

【缺图处理】
- 槽位标签："🖼 效果图（缺图）"——红色高亮
- 用户可选：① 从图片池选 ② AI 生成补位图 ③ 保留占位（导出时显示"待补图"）
```

**关键约束（红线）**：
- **禁止静默铺满**：批量填图必须展示预览，用户逐页确认后才执行（撞"本地优先+人工确认"红线）
- **禁止 AI 自动配图为主力**：AI 生图仅用于"缺图补位"场景，不可作为默认图片来源

**前端交互**：
- 槽位状态可视化：空槽（灰色）→ 推荐中（闪烁）→ 已填（缩略图）→ 锁定（带🔒图标）
- 页面状态：Draft → Reviewed → Locked（Pitch 的 Slide 状态启发）
- 底部工具栏：批量填图按钮、全部锁定按钮、导出 PPTX 按钮

**验收标准**：
- 批量填图推荐：用户采纳率 ≥ 50%
- 单点替换：从点击到图片替换完成 ≤ 3 秒
- 页面状态切换：Draft↔Reviewed↔Locked 流畅切换，状态持久化

#### Phase 4：AI 生图补位（中期，8-12 周）

**目标**：当项目图片池没有合适的图时，AI 生成补位图。

**两个场景**：

**场景 A：PPT 页面内嵌补图（Adobe Firefly 启发）**
```
用户在 PPT 编辑器中框选一个空白区域
    ↓
输入描述："生成一张现代高层住宅的效果图，玻璃幕墙，黄昏光线"
    ↓
选择参考图（可选，从项目图片池选 1-3 张作为风格锚点）
    ↓
AI 生成（调用外部 API：Krea/PromeAI/Midjourney/Firefly）
    ↓
生成结果自动匹配页面整体色调（Harmonize）
    ↓
用户确认 → 插入槽位 → 归入项目图片池
```

**场景 B：快速概念草图（Krea 启发）**
```
用户在"生图工作台"上传手绘草图或 3D 模型截图
    ↓
选择场景类型（建筑/室内/景观）+ 风格模板（写实/概念/水墨）
    ↓
调节参数：写实度、风格化程度、AI 自由度（Krea 的 AI Strength）
    ↓
实时预览（低分辨率实时渲染，参考 Krea 的 50ms 反馈）
    ↓
生成 4 张变体 → 选中放大 → 下载/插入 PPT
```

**技术策略**：
- **不自研底层模型**：ROM-AI 是"认知管理工具"不是"图像生成引擎"
- **多模型聚合**：根据场景自动选择轻量模型（快速探索）或高质量模型（最终输出）
- **本地优先**：AI 生成参数和图片缓存保存在本地，生成图片自动归入项目图片池

**验收标准**：
- 场景 A：从描述到生成完成 ≤ 30 秒（取决于 API 延迟）
- 场景 B：草图上传到低分辨率预览 ≤ 5 秒（取决于本地模型/API）
- 生成图片自动分类：系统能正确识别生成图片的 asset_type（如"render"）

#### Phase 5：协作编辑 + 版本管理（长期，12 周以后）

**目标**：主创、设计师、营销、商务一起修改 PPT 底稿。

**借鉴 Pitch 的协作深度**：
- **Slide 状态**：哪页已确认、哪页缺图、谁负责（Pitch 的"Slide 状态"独有功能）
- **评论**：页面级评论 + 标注（"这个入口方向不对"）
- **版本历史**：每次 AI 生成/人工替图后自动快照，可回溯
- **演示分析**：追踪甲方查看汇报材料的次数和停留时间（中期可做）

## 五、具体研发建议（五类标注）

| 建议项 | 分类 | 落点 | 说明 |
|--------|------|------|------|
| **PPT 图文大纲编辑器前端界面** | 需要补 UI | 共创营地 → 新 Tab"PPT 大纲" | 左侧大纲导航+中间编辑+右侧图片槽位，参考 EasyMap 布局 |
| **Slide 数据结构扩展** | 已可实现 | 会议纪要/技能模块 → data 结构 | 新增 `asset_type`、`imageSlots`、`status` 字段，已有 `visualSuggestion` 兼容 |

| **批量填图预览 + 确认** | 需要补 UI | 共创营地 → PPT 编辑器 | 必须展示预览，用户确认后才执行（红线） |

| **AI 生图补位（PPT 内嵌）** | 需要单独拍板 | 共创营地 → 图片槽位 | 需确定接入哪个外部 API（Krea/PromeAI/Firefly），成本与商用安全评估 |
| **实时概念草图（Krea 模式）** | 需要单独拍板 | 共创营地 → 新"生图"Tab | 需确定是本地部署模型（ComfyUI/SD）还是调用 API，算力成本评估 |
| **协作评论** | 需要补 UI + 需要单独拍板 | 共创营地 → PPT 编辑器 | 需确定评论数据结构、与会议纪要模块的耦合方式 |
| **版本历史** | 需要补数据 | 后端 → 快照机制 | 每次替图/改字后自动快照，存储策略（全量 vs 增量）需拍板 |
| **导出 PDF/PNG/SVG** | 暂不做 | 汇报出口 | 已有 PPTX 导出，其他格式排 P2 |
| **品牌 Kit（色/字体/Logo）** | 需要单独拍板 | 全局设置 | 类似 Canva Brand Kit，需事务所确认品牌规范 |
| **网页预览 Deck** | 暂不做 | 汇报出口 | ROM-AI 以 PPTX 为最终交付物，网页预览可排 P2 |
| **实时多人协作编辑** | 暂不做 | 共创营地 | 技术复杂度高，排长期 |
| **PPT 导入（读入已有 PPT）** | 暂不做 | 共创营地 | 类似 Plus AI，排中期 |

## 七、验收标准与优先级

### 7.1 Backlog 排序（P0/P1/P2）

| 优先级 | 功能 | 预计工期 | 验收标准 |
|--------|------|---------|---------|
| **P0** | PPT 图文大纲编辑器前端 | 2-3 周 | 从项目资料生成 12-20 页大纲，每页可编辑标题/要点/图片槽位，导出 PPTX 格式正确 |
| **P0** | 项目图片池画廊前端 | 1-2 周 | 展示从 PPT/PDF/Word/图片包提取的所有图片，支持分类筛选和搜索 |
| **P0** | 图片槽位推荐算法 | 1 周 | 基于 `asset_type` 从图片池推荐 3 张，用户采纳率 ≥ 50% |
| **P1** | 批量填图 + 确认 | 2 周 | 展示所有槽位的推荐图预览，用户逐页/全部确认后执行，禁止静默铺满 |
| **P1** | 页面状态（Draft/Reviewed/Locked） | 1 周 | 状态切换流畅，持久化，Pitch 式 Slide 状态管理 |
| **P1** | AI 生图补位（PPT 内嵌） | 3-4 周 | 框选空白区域→描述→生成→插入槽位，≤30 秒 |
| **P2** | 实时概念草图（Krea 模式） | 4-6 周 | 草图上传→实时预览→生成 4 张变体，≤5 秒低分辨率预览 |
| **P2** | 协作评论 | 2-3 周 | 页面级评论，标注在图片/文字上，与会议纪要打通 |
| **P2** | 版本历史 | 2-3 周 | 每次替图/改字自动快照，可回溯对比 |
| **P3** | 品牌 Kit | 2 周 | 事务所品牌色/字体/Logo 一次定义，全局应用 |
| **P3** | 导出 PDF/PNG/SVG | 1-2 周 | 在 PPTX 基础上导出其他格式 |
| **P3** | PPT 导入（读入已有 PPT） | 3-4 周 | 读入 PPT 后继续生成 1.1、1.2 版本 |

### 7.2 关键指标（KPI）

| 指标 | 目标 | 测量方式 |
|------|------|---------|
| 大纲生成到导出的端到端时间 | ≤ 5 分钟（含人工审查） | 用户测试 |
| 图片推荐采纳率 | ≥ 50% | 日志统计 |
| 图片槽位空填率（导出时） | ≤ 20% | 导出文件分析 |
| PPTX 格式正确率 | ≥ 95%（无崩图、无错位） | 抽样检查 |
| 用户满意度（半自动 vs 全自动） | ≥ 4/5 | 用户访谈 |

## 八、关键边界判断（红线）

| 能力 | 该做 / 不该做 | 理由 | 参考竞品 |
|------|-------------|------|---------|
| AI 自动配图为主力 | ❌ **不该做** | 建筑图不能 AI 幻觉；无合适图就黑占位/标缺图 | Gamma 的自动配图是最大投诉来源 |
| 批量填图预填+确认 | ✅ **必须做** | 借鉴 EasyMap，但必须加确认闸（已批决议：不静默执行） | EasyMap BATCH FILL |
| 本地项目资产池为主 | ✅ **必须做** | 本地优先原则，不依赖外部素材库 | 与 Canva 的 100M+ 素材库形成差异化 |
| 网页原生 Deck 为主形态 | ❌ **不做** | ROM-AI 以 PPTX 为最终交付物 | Gamma 导出 PPT 频繁崩坏 |
| 自研底层生图模型 | ❌ **不做** | 与"认知管理"定位偏离，集成外部 API | Krea 不自研模型，集成 60+ 模型 |
| 实时多人协作编辑 | ⚠️ 长期做 | 技术复杂度高，先跑通单人链路 | Pitch 的协作深度是长期目标 |
| 商用安全审查 | ✅ **中期做** | 甲方/投标场景的版权风险必须可控 | Adobe Firefly 的授权训练+法律兜底 |
| 建筑师主导判断 | ✅ **核心原则** | 所有 AI 输出必须人工确认，不静默执行 | ROM-AI 已批铁律 |

## 九、一句话总结

> **ROM-AI 共创营地的"生图+生 PPT"不是要做"更强的 AI 自动生成工具"，而是要做"更可靠的项目资料组织器"——把甲方的诉求、会议的决议、项目的图片、团队的判断，组织成一套可审查、可替换、可导出的图文研判底稿。EasyMap 的占位骨架、Krea 的实时画布、Firefly 的框选补位，都是手段；最终目的是让建筑师在投标前三天，不是手忙脚乱地找图拼 PPT，而是打开 ROM-AI，看到一套已经排好、图已填好、判断已写好的底稿，只需确认、微调、导出。**
