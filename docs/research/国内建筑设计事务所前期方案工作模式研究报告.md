## 一、规划条件解读

### 1.1 真实工作模式描述

国内建筑设计事务所在项目启动阶段，首先面临的是规划条件的解读与整理工作。根据 goa 大象设计在重庆观音桥项目中的实践，规划条件涉及"用地红线、容积率、建筑密度、限高、退界"等刚性指标，以及地下步道、步行通廊、视线通廊等上位规划要求。goa 的处理方式是"整体思维"——不仅被动读取规划条件，而是基于交通和空间研究反推解决方案，并与政府积极沟通获得支持。

**信息获取渠道**：
- 土地出让文件 / 控制性详细规划（控规）公示文件
- 规划局出具的设计条件通知书
- 城市设计导则 / 风貌管控要求
- 与属地规划和自然资源部门的沟通会

**结构化整理方式**：
- 将规划条件按"刚性指标"和"弹性引导"分类整理
- 制作"规划条件对照表"，逐条标注设计响应策略
- 对多地块项目（如 goa 的观音桥 5 地块）建立地块间关联分析矩阵

### 1.2 关键痛点 / 机会点

| 痛点 | 具体表现 |
|------|----------|
| 规划条件来源分散 | 控规、出让条件、城市设计导则、口头要求并存，缺乏统一入口 |
| 非标准化解读 | 年轻建筑师对规划条件的理解深度不一，容易遗漏隐性约束 |
| 动态变更 | 规划条件在方案推进过程中可能调整，版本管理混乱 |
| 多地块关联复杂 | 综合体项目涉及多个地块的联动规划，人工分析容易遗漏 |

### 1.3 与 AI 系统介入的契合点

- **自动提取结构化规划条件**：从 PDF 控规文件/设计条件通知书中自动提取指标（容积率、密度、限高、退界等），生成结构化表格
- **指标合规实时校验**：在方案调整过程中实时计算并提示是否超规
- **多地块联动分析**：自动识别多地块间的交通/视线/空间通廊要求，生成关联分析矩阵
- **规划条件版本管理**：自动追踪规划条件的变更历史，标注影响范围

## 二、竞品对标（类比项目分析）

### 2.1 真实工作模式描述

国内建筑设计公司的"竞品对标"主要表现为**可类比项目分析**（Comparable Project Analysis）。在房地产项目策划中，可类比项目分析的重点包括：

**对标维度**：
- 项目概况（区位、规模、产品类型）
- 市场定位（目标客群、产品档次）
- 价格体系（售价/租金水平）
- 硬件指标（容积率、户型配比、面积段）
- 销售对策（开盘策略、推广节奏）
- 主要媒体运用及投放频率
- 公关促销活动与特殊卖点

**信息收集渠道**：
- 建筑/设计类门户网站（谷德、ArchDaily、Dezeen）
- 地产类数据平台（中指、克而瑞）
- 设计院内部案例库（过往项目）
- 实地考察与照片采集
- 甲方提供的对标项目清单

从设计方法论角度，国内设计师的习惯是"临时抱佛脚式"——拿到任务书后从网络搜集案例，进行"头脑风暴"，但由于时间压力往往浅尝辄止。而国外事务所（如 goa 的合作方）更注重平时的知识积累和系统性研究，形成长期的对标数据库。

### 2.2 关键痛点 / 机会点

| 痛点 | 具体表现 |
|------|----------|
| 案例收集碎片化 | 案例散落在个人电脑、公司服务器、网络各处，缺乏统一检索 |
| 对标维度不系统 | 分析停留在视觉形式层面，缺乏对规划策略、空间组织、技术细节的深入对比 |
| 过往项目经验未复用 | 每个项目从零开始，没有调用历史项目数据 |
| 缺乏数据支撑 | 对标分析定性多于定量，缺乏面积指标、造价、能耗等量化对比 |

### 2.3 与 AI 系统介入的契合点

- **智能案例库检索**：基于项目类型、区位、规模、规划指标等维度，自动推荐历史项目和公开案例
- **多维度对比矩阵**：自动生成竞品对比表（功能布局、立面策略、空间组织、技术亮点等）
- **历史项目数据调取**：自动关联本公司的过往对标项目，提取设计策略、指标参数、甲方反馈
- **AI 辅助案例分析**：自动提取案例的关键设计策略（如 goa 的"梯坎"策略、直向的"场地回应"策略），形成可复用的策略卡片

## 三、方案评审流程

### 3.1 真实工作模式描述

国内设计院的方案评审体系通常分为三级：

**1. 内审（设计院内部审查）**
- 由总工办/技术质量部组织
- 参与人员：总建筑师、各专业总工、项目经理
- 审查内容：方案的技术可行性、规范合规性、设计深度
- 输出：内审意见单，需设计团队逐条回复并修改

**2. 外审（向政府/评审机构提交）**
- 以广州市的建筑景观设计方案评审为例：
  - 建设单位向第三方机构提出评审申请
  - 需提交不少于两个不同设计风格的方案进行比选（景观敏感地区需三个）
  - 第三方机构 10 个工作日内组织专家评审会议
  - 评审会议需邀请不少于 5 名专家（单数）及 1 名属地规划和自然资源部门负责人员
  - 采用无记名投票方式，2/3 以上专家推荐票为通过
  - 未通过的方案需修改后重新申请，两次未通过由规划部门指导修改

**3. 专家会（专项评审）**
- 如 GAD 参与的礼贤未来社区项目，经历"专家委员会集中评审"
- 由绿城设计院、生活集团协同项目推进办完成汇报答辩
- 通过后启动土地挂牌审批流程

**评审维度**（基于多源信息综合）：
- 功能合理性（空间布局、流线组织）
- 日照与采光（大寒日日照时数、采光系数）
- 交通组织（人车分流、停车配置、消防环道）
- 造价控制（单方造价、限额设计指标）
- 消防合规（防火间距、疏散距离、消防登高面）
- 城市空间与风貌（天际线、界面连续性、街道活力）
- 绿色建筑与节能（能耗指标、可再生能源利用）

### 3.2 关键痛点 / 机会点

| 痛点 | 具体表现 |
|------|----------|
| 评审标准不统一 | 不同专家/不同城市的评审标准差异大，难以预判 |
| 修改反复耗时 | 专家意见"大而全"，设计团队需逐条消化，修改周期不可控 |
| 内审流于形式 | 部分设计院内审缺乏深度，仅做"走过场" |
| 评审意见缺乏结构化 | 专家意见以口头/手写为主，难以转化为可执行的设计修改清单 |
| 多方案比选成本高 | 每个方案需完整出图，人力成本巨大 |

### 3.3 与 AI 系统介入的契合点

- **评审标准库**：建立不同城市/不同类型项目的评审标准数据库，预判评审关注点
- **AI 辅助预审**：在正式提交前，模拟专家视角进行预审（如日照合规、消防距离、规范条文匹配）
- **评审意见结构化**：将专家意见自动分解为"可执行任务"，关联到设计图纸的具体位置
- **多方案智能比选**：AI 辅助生成多方案变体，自动计算各方案的指标差异（容积率、造价、日照等）
- **评审意见版本追踪**：追踪历次评审意见的修改状态，避免遗漏

## 四、甲方沟通与画像

### 4.1 真实工作模式描述

国内建筑设计公司的甲方（业主）主要分为三类：

**1. 地产商（开发商）**
- 关注重点：成本控制、销售去化、产品标准化、品牌溢价
- 沟通特点：决策链条相对短，但可能因市场变化频繁调整定位
- 管理策略：goa 提出"以倾听为基础"——深刻理解甲方真正期待，而非简单回应每个具体要求

**2. 政府机构**
- 关注重点：公共利益、城市空间品质、风貌管控、合规性
- 沟通特点：决策流程长，需经过多层汇报和审批
- 管理策略：如礼贤未来社区案例中，成立"工作专班"，采用"扁平、一体、高效"的组织方式推进

**3. 企业自用（企业总部/产业园）**
- 关注重点：企业文化表达、空间效率、员工体验、长期运营
- 沟通特点：使用部门参与度高，需求多元且个性化
- 管理策略：需要深入了解使用方的业务流程和空间使用习惯

**goa 的沟通方法论**：
- "以倾听为基础"——整合开发者、使用者、社会公众的声音
- "以合作为支撑"——与业主、合作顾问、施工单位建立积极紧密的合作关系
- "以 1:1 理念为实践准则"——通过现场制作 1:1 模型让甲方亲身体验空间尺度

### 4.2 关键痛点 / 机会点

| 痛点 | 具体表现 |
|------|----------|
| 甲方需求模糊且动态 | 甲方前期需求表述不清晰，设计过程中不断"觉醒"新需求 |
| 信息传递失真 | 甲方决策层→设计部→设计院，需求层层传递后失真 |
| 多方利益冲突 | 政府、开发商、使用者、周边居民等多方诉求冲突 |
| 缺乏甲方画像系统 | 不同甲方类型的决策习惯、关注重点、沟通偏好未形成系统化知识 |
| 沟通记录碎片化 | 会议纪要、微信记录、邮件分散，难以形成完整沟通档案 |

### 4.3 与 AI 系统介入的契合点

- **甲方画像自动生成**：基于项目类型、业主性质、历史合作记录，自动生成甲方画像（关注优先级、决策风格、关键决策人）
- **需求智能澄清**：对甲方模糊需求进行结构化拆解，自动追问缺失信息
- **沟通记录统一归档**：自动整合会议纪要、微信、邮件中的沟通要点，生成"沟通时间线"
- **多方利益冲突预警**：识别不同利益相关方的潜在冲突点，提前准备协调方案
- **设计决策可追溯**：每个设计决策关联到对应的甲方沟通记录，避免"说不清"

## 五、会议纪要管理

### 5.1 真实工作模式描述

建筑设计项目的会议体系包括：
- 项目启动会（任务交底、团队分工）
- 方案讨论会（内部头脑风暴）
- 甲方汇报会（方案汇报、意见收集）
- 专家评审会（方案评审）
- 销项整改会（问题跟踪）
- 监理例会（施工阶段）

从现有信息看，会议纪要的管理处于相对传统的状态：
- 会议纪要以 Word/邮件形式下发
- 包含"上次会议议定事项落实情况"的追踪机制
- 需明确责任单位、完成时间、验收标准
- 但会议决议到可执行任务的转化依赖人工，缺乏自动化跟踪

### 5.2 关键痛点 / 机会点

| 痛点 | 具体表现 |
|------|----------|
| 会议决议落实率低 | 会议讨论热烈，但会后缺乏跟踪，大量决议不了了之 |
| 任务分配模糊 | "这个再优化一下""那个再考虑一下"，缺乏明确的负责人和 deadline |
| 会议信息孤岛 | 不同会议（甲方会、内审会、专家会）的信息未打通 |
| 历史会议不可检索 | 过往项目的会议经验无法被新项目调用 |
| 跨专业任务依赖不清 | 建筑、结构、机电等专业的任务先后依赖关系未显性化 |

### 5.3 与 AI 系统介入的契合点

- **会议录音自动转写 + 结构化提取**：将语音会议自动转写为文字，提取"决议项、负责人、Deadline"三要素
- **任务自动拆解与派发**：将会议决议自动拆解为任务卡片，推送给对应责任人
- **任务依赖自动识别**：识别任务间的专业依赖关系（如建筑方案确定后才能启动结构计算），自动生成任务网络图
- **逾期预警与提醒**：对临近 deadline 未完成的任务自动预警
- **会议知识沉淀**：将项目会议中的关键决策和教训自动归入知识库，供新项目检索

## 六、知识沉淀

### 6.1 真实工作模式描述

建筑设计事务所的知识沉淀目前处于"文档管理"向"知识管理"过渡的阶段：

**现有沉淀方式**：
- 项目档案（图纸、文本、照片）归档到服务器或云盘
- 设计规范、标准图集集中管理
- 项目复盘总结（部分公司有）
- 内部培训/案例分享会（形式化较多）

**先进理念（参考硬件研发知识管理）**：
- 知识管理的核心不是"把文档集中存放"，而是让经验形成"可追溯、可验证、可复用的组织资产"
- 从"文件管理"转向"知识对象管理"——每个知识对象包含：背景、根因、措施、验证、复用建议、适用边界
- 将知识沉淀嵌入 IPD 阶段门：每个阶段门不仅检查交付物，还要检查"本阶段产生了哪些可复用知识"

**建筑设计领域可沉淀的知识类型**：
- 设计策略（如 goa 的"梯坎"商业空间策略、直向的"场地回应"策略）
- 平面模式（特定功能类型的高效布局模式）
- 示范区经验（样板区选址、流线、体验设计）
- 规范应对技巧（消防、日照、节能的灵活应对方法）
- 甲方沟通经验（不同类型甲方的决策偏好和沟通策略）
- 跨专业协调经验（机电与建筑冲突的典型解决方案）

### 6.2 关键痛点 / 机会点

| 痛点 | 具体表现 |
|------|----------|
| 知识存在于个人大脑中 | 资深设计师的经验未显性化，离职即流失 |
| 项目档案利用率低 | 结项后项目资料沉睡在服务器，新项目难以检索调用 |
| 缺乏标准化知识模板 | 复盘文档格式各异，信息密度低，难以快速提取关键信息 |
| 知识复用机制缺失 | 工程师不知道"哪些知识可以复用""复用时要注意什么边界" |
| 知识更新滞后 | 规范变化、技术更新后，旧知识未及时标记失效 |

### 6.3 与 AI 系统介入的契合点

- **AI 辅助知识萃取**：自动从项目文档（文本、图纸、邮件）中萃取关键设计策略和经验
- **知识对象标准化**：将项目经验封装为标准化"知识卡片"（背景、策略、适用边界、验证数据、更新记录）
- **新项目智能推荐**：项目启动时，自动推荐相似项目的历史知识和风险清单
- **设计评审检查清单动态生成**：基于历史问题库，自动生成设计评审的检查清单（如"某类项目常出现的消防问题"）
- **知识复用闭环追踪**：记录知识被复用的效果，反馈更新知识库

## 七、行业综合痛点与 AI 系统介入的整体契合度评估

### 7.1 行业核心痛点汇总

基于搜索结果，国内建筑设计行业前期方案阶段的核心痛点可归纳为：

1. **效率低下**：传统设计方式步骤繁琐，信息传递路径过长，工作重复率高
2. **信息交流不畅**：多专业、多参与方之间信息传递不完整，数据标准不统一
3. **方案反复修改**：甲方需求动态变化，每次修改需投入大量时间精力
4. **设计碎片化**：建筑、结构、机电等专业各自为战，信息孤岛导致频繁冲突
5. **资源分配不合理**：忙闲不均，热门项目经验设计师短缺，新手难以承担重任
6. **质量把控困难**：缺乏有效的质量评价手段和统一标准
7. **技术创新滞后**：3D 建模、BIM、AI 等新技术应用不足

### 7.2 AI 系统介入的整体机会矩阵

| 工作维度 | 痛点严重程度 | AI 介入可行性 | 预期价值 |
|----------|-------------|--------------|----------|
| 规划条件解读 | ★★★ | ★★★★★ | 自动提取指标、实时合规校验 |
| 竞品对标 | ★★★ | ★★★★ | 智能案例推荐、多维度对比矩阵 |
| 方案评审 | ★★★★ | ★★★★ | AI 预审、意见结构化、多方案比选 |
| 甲方沟通 | ★★★★ | ★★★ | 甲方画像、需求澄清、沟通归档 |
| 会议纪要 | ★★★ | ★★★★★ | 语音转写、任务自动拆解、逾期预警 |
| 知识沉淀 | ★★★★★ | ★★★★ | 知识萃取、智能推荐、复用闭环 |

### 7.3 优先切入建议

基于"痛点严重性 × AI 可行性 × 价值产出"的综合评估，建议 AI 系统优先切入以下三个场景：

**第一优先：会议纪要管理 → 任务追踪**
- 原因：痛点明确、技术成熟（语音识别 + NLP）、见效快
- 价值：直接提升项目执行效率，减少"决议不了了之"的损耗

**第二优先：规划条件解读**
- 原因：信息结构化程度高，规则明确
- 价值：在项目最前期建立合规基线，减少后期返工

**第三优先：知识沉淀**
- 原因：长期价值最大，但实施难度较高
- 价值：从"项目制"向"能力制"转型，减少重复试错成本
