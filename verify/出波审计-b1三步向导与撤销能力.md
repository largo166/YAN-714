# 出波审计 · b1 清理浮层升级为"仓库/选取/执行"三步向导

> 用户指令(2026-07-06):出波项①——先审计现有浮层与配置端点现状,报增量后作为独立半波。本文只审计报增量,**不实做**。

## 一、现状(代码级)

### 现有 CleanupOverlay(b1 权威清理面)
已实现完整闭环:`status → scan(只读) → preview(只读) → apply(两步确认+后端 confirm 双闸) → restore(一键撤销)`。作用于**已配置的工作目录**(`workspace_path`),清理候选按规则(tmp/bak/log/缓存/副本)移入 `_ROMAI_CLEANUP_QUARANTINE/<ts>/`,永不删除。

### 配置端点现状
| 能力 | 端点 | 现状 |
|---|---|---|
| 工作目录配置 | `POST /api/workspace/config` | **只写不校验存在性**:`set_config` 直接存 path,仅返回 `accessible=Path(path).is_dir()`;传不存在的路径会存进去,到 scan 才暴露"不可访问" |
| 收件箱配置 | `POST /api/inbox/config` | 存在性校验较严(不存在→400) |
| 仓库根配置 | `updateSettings({repository_root_path})` | 只写路径 |
| **建目录/建仓库** | **无** | 后端只有 `config.py` 里系统级 `DATA_DIR.mkdir`(自建数据目录),**没有任何"用户指定路径→新建目录"的端点** |

## 二、三步向导增量评估

设想的向导:**① 仓库(选/建工作目录) → ② 选取(扫描+预览候选) → ③ 执行(确认清理+撤销)**。

- **步骤②③ = 零增量**:scan/preview/apply/restore 端点全现成,CleanupOverlay 已实现,只需重排为向导式布局(纯前端 UI 编排)。
- **步骤① "选" = 小增量**:`workspaceConfig` 端点在,前端 SettingsOverlay 已能配工作目录;向导内嵌一个路径输入+"设为工作目录"即可,复用现有端点。
- **步骤① "建仓库" = 新后端管线(须单独拍板)**:后端**无**"新建目录"端点。要让用户在向导里"建一个新仓库文件夹",必须新增一个 `POST /api/workspace/mkdir`(或等价)——这**触发"一写新管线就停"红线**。且建目录涉及文件系统写权限/路径校验/防逃逸,是有安全面的新动作,不能顺手加。

## 三、增量结论与建议

| 增量项 | 性质 | 判定 |
|---|---|---|
| 向导式三步布局重排 | 纯前端 | ✅ 可做(独立半波) |
| 步骤① 选取已有目录设为工作目录 | 复用 `workspaceConfig` | ✅ 可做 |
| 步骤① **新建仓库目录** | **新后端端点** | ⛔ 踩红线,须单独拍板后才做 |
| workspace/config 存在性校验补齐 | 后端 3 行(与 inbox/config 对齐) | 🟡 建议顺带修(现在能存无效路径),但属后端改动,拍板时一并定 |

**建议**:三步向导半波先做"选已有目录"版本(纯前端+复用端点,零红线);"建新仓库"作为该半波内的一个待拍板子项,连同 workspace/config 校验补齐一起决策后再动后端。

# 附:撤销能力审计结论(随波交付)

用户指令:撤销能力审计结论随波交付。

- **撤销真源**:清理的撤销(restore)=`POST /api/workspace/cleanup/restore`,按 apply 返回的 `manifest.timestamp` 从隔离区把文件移回原位。
- **本波后归属**:营地清理卡已**收回独立执行权**(ADR-001),清理与撤销的唯一权威操作面收敛到 **b1 CleanupOverlay**。营地只做"去数据基地清理"的深链跳板,不再持有 apply/restore。
- **撤销的既有边界(如实,未改)**:撤销仅"本次会话有效"——`lastQuarantine` 时间戳只存 CleanupOverlay 组件内存,刷新/切页后撤销按钮消失;磁盘 manifest 支持按时间戳恢复,但 **UI 无历史隔离批次列表**,老批次只能手动进 `_ROMAI_CLEANUP_QUARANTINE/` 找。
- **已知脆弱点(未改,记录在案)**:`workspace.py cleanup_apply` 的 `shutil.move` 未逐项 try——单文件被 Windows 锁占用即抛 500 且 manifest 不落盘,本批已移文件失去 API 恢复入口。这是后端健壮性问题,属另外的拍板,本波(纯前端 composer 波)未触及。

**结论**:撤销能力完整可用且已正确收敛到 b1 权威面;"跨会话撤销/历史批次列表/apply 逐项容错"是可选增强,均需后端改动,列入"清理三步向导半波"或后续拍板,不在本波范围。
